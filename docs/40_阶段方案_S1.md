## 4. 技术路线

### 4.1 备选方案

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A** | 以 `dsh_foc`(feature) 为底**复制工作树**到 `cubli`，改名 + 移植 IMU | FOC 是主体，改动面最小；保留 #173 全部修复 | 需把调试口从 USART1 挪到 USART2 | ✅ **采用** |
| B | 从 `dsh_foc` 直接拉新分支开发 | 免复制 | 两件不同的产品塞进一个仓库，`docs`/`workflow` 互相污染 | ❌ |
| C | 以 `gyroscope` 为底再移植 FOC | IMU 现成 | FOC 有 30+ 文件、20 kHz 时序与保护，搬家风险远大于搬 IMU | ❌ |
| D | 新建 CubeMX 工程、两边的代码逐个挑选移植 | 最干净 | 等于把已验收的 10 个阶段重做一遍，S7~S10 的实测结论全部要重验 | ❌ |

### 4.2 选定路线（方案 A）的关键决定

**决定 1：两个串口驱动**各自独立，不共用一套字节流。

- `bsp_uart`（调试）= USART2 + DMA1_CH3/CH4（实测映射，见 `19` 号文档第 9 节），沿用 dsh_foc 现有 API（`bsp_uart_write` / 环形缓冲 / 回调），只把硬编码的 `huart1`/`hdma_usart1_rx` 改成**可配置句柄**。
- `bsp_imu`（IMU）= USART1 + DMA1_CH1/2，从 gyroscope 移植，**只把 DMA 通道从 CH3 改 CH1**（CH3 归 SPI1 编码器）。

理由：两路的语义完全不同（文本命令 vs 二进制帧流），混在一个环形缓冲里要靠 CRC 过滤，一旦丢字节会污染命令解析；分开后各自的坏帧只影响自己。

**决定 2：IMU 帧解析与姿态解算分两层。**

S1 只移植 `mid_fdilink`（字节流 → 结构体，含 CRC），**不**移植 `mid_att`。姿态解算在 S2 单独做，因为它要改坐标系、要去掉模块内部的融合假设。

**决定 3：`FW_BUILD_ID` 从 1 重新起。**

`cubli` 是新产品，不是 `dsh_foc` 的续作；沿用 173 会让"版本号 +1"规则失去意义。三处（`.ioc` 里没有、`board_cfg.h`、`uvprojx` 的 `-D`）必须同步，`doc_check.py` 负责查一致。

**决定 4：工程名 `cubli`，产物 `cubli.axf`。**

`myfoc.uvprojx` → `cubli.uvprojx`；`MDK-ARM` 目录结构保留，`UV4.exe -b` 命令随之改。

| 步 | 执行方 | 动作 | 完成判据 |

| 2 | 开发方 | 把 `dsh_foc`(feature, `d7e08b5`) 的 `User/` 合并进 `cubli\User\`；`Drivers/` 与生成侧一致则不动 | `git status` 可枚举；`User/` 与源工程逐文件一致 |
| 3 | 开发方 | 把 `User\**\*.c` 加进 `cubli.uvprojx` 分组、补 include 路径与 `-D` 宏（对照 dsh_foc 的 uvprojx） | 构建 0E0W，资源数字与 dsh_foc 接近 |

| 5 | 开发方 | 把 `bsp_uart` 的调试口从 USART1 切到 USART2（句柄参数化 + 回调判断改实例） | 构建 0E0W；`bsp_uart` 内无 `huart1` 残留 |

> **分工变更（2026-11-03）**：CubeMX 工程由**用户**在 GUI 里生成（第 1 步），开发方不代跑 CubeMX。
> 理由：`myfoc.uvprojx` 已被手工改过 12 次，若由 CubeMX 完整重生成会丢失 `User/*.c` 分组、include 路径与 `-D` 宏；
> 由用户生成 `Core/`+`Drivers/`+空白 `uvprojx`，开发方再把 `User/` 与工程设置补回去，损失可控且每一步都能用构建验证。
> 第 1 步不通过（41 号自检有任意一项不符）时，不进入第 2 步。

### 5.1 主机测试（L2）要覆盖什么

S1 的主机测试不追求覆盖率，只锁住"合并过程有没有把已验收的逻辑改坏"：

| 用例 | 断言 |
|---|---|
| Clarke/Park 恒等式 | 固定输入下输出与 golden 值一致 |
| SVPWM 扇区与占空比 | 三相占空比 ≤ 上限、和 ≤ 常数 |
| PI 限幅与抗饱和 | 积分不越界 |
| 电流零漂补偿 | 补偿前后 offset 收敛 |
| `mid_fdilink` 解析 | 喂一帧真实抓包 → 字段值精确匹配；CRC 错帧被丢弃 |
| 环形缓冲 | 写满/读空/回绕三种边界不丢不重 |

## 7. 风险与对策

| # | 风险 | 概率 | 后果 | 对策 |
|---|---|---|---|---|
| R1 | CubeMX 重新生成把 USER CODE 之外的改动冲掉 | 中 | 编译失败或行为变化 | 改 `.ioc` 前先提交一次干净状态；生成后 `git diff` 逐行看，只接受外设初始化相关变化 |
| R2 | USART1 从调试口变 IMU 口后，`app_cmd`/`mid_log`/`mid_vofa` 隐式依赖 `huart1` | **高** | 命令无输出 | 步骤 4 后全局 grep `huart1`，逐个改为 `huart2` 或句柄参数 |
| R3 | DMA1 通道冲突（USART1 RX 要 CH1，编码器要 CH3） | 中 | 编码器或 IMU 收不到数据 | 严格按 §1 的表分配；`DMA_HandleTypeDef` 初始化后用 `stat` 命令打印各通道启用状态 |
| R4 | fake HAL 桩不全导致主机测试编不过 | 高 | A-2 卡住 | 先只桩住新用到的 USART2/DMA 符号，缺失符号按编译错误逐个补，不做"全量桩" |
| R5 | 复制时把 `dsh_foc` 的构建产物（`.o`/`Objects`）一起带进来 | 中 | 构建输出混乱 | 复制后立刻 `git clean -xdn` 预览再删；`.gitignore` 已排除 |
| R6 | 无感代码在 #173 里默认线程仍会跑 | 低 | 白耗 CPU | 步骤 2 时确认速度源宏为 `ENC_SPD_SRC_PLL`，并在 `stat` 里打印当前速度源 |

## 8. 回退方案

- 每个步骤一个独立提交，**任何时候都能 `git reset --hard <上一个提交>` 退回可构建状态**。
- 步骤 3（改 `.ioc` 重新生成）风险最大，单独提交，并在提交信息里写明"仅外设初始化变化，未动 USER CODE"。
- 若 USART2 路线在图传/接线层面走不通（如 CH340N 未被焊接），回退到"USART1 调试 + IMU 暂缺"的临时状态，S2 顺延——**但必须先回来更新本文与 `18`，不允许静默改路线**。
