# 主框架

> 代码位置：`User/`（**S0 尚未创建 Keil 工程**）
> 本文是整套工程的"总图"：**分层、时序、优先级、状态机、目录约定以本文为准**。
> 标注说明：**【继承】**= 来自 `dsh_foc` 已验收代码；**【新增】**= 本工程要写；**【规划】**= 尚未实现。
> 最后更新：2026-11-03

---

## 1. 职责边界

主框架不实现控制算法，只定义：

- 代码分层与依赖方向（谁能调谁）
- 三个时基（20 kHz / 1 kHz / 200 Hz）的**分工与时间预算**
- 中断优先级分配
- 全局状态机与初始化顺序
- 目录与命名约定

**不负责**：FOC 数学（见 `workflow` 与本工程后续 1x 子文档）、IMU 协议解析、平衡律整定。

## 2. 分层结构

```
┌───────────────────────────────────────────────────────────────────┐
│ App  应用层   app_main / app_state(状态机) / app_cmd(命令)          │
│              app_balance【新增】平衡任务编排                        │
│              只做"什么时候干什么"，不做数学                          │
├───────────────────────────────────────────────────────────────────┤
│ Alg  算法层   alg_svpwm / alg_clarke / alg_park / alg_pi / alg_foc │
│              alg_bal【新增】平衡控制律（LQR 或串级 PID）            │
│              纯数学，无 HAL 依赖，可在 PC 上单元测试                 │
├───────────────────────────────────────────────────────────────────┤
│ Mid  中间件   mid_current / mid_angle / mid_ringbuf / mid_log      │
│              mid_fdilink【新增】IMU 帧解析                          │
│              mid_att【新增】姿态角解算与坐标系变换                  │
├───────────────────────────────────────────────────────────────────┤
│ Bsp  驱动层   bsp_pwm / bsp_adc / bsp_ssi / bsp_uart / bsp_gpio     │
│              bsp_imu【新增】IMU 串口收发（DMA）                     │
│              唯一允许直接调 HAL 的层                                │
├───────────────────────────────────────────────────────────────────┤
│ Core CubeMX  外设初始化（MX_xxx_Init），只在 USER CODE 段扩展       │
└───────────────────────────────────────────────────────────────────┘
```

**依赖方向严格单向向下**：App → Alg → Mid → Bsp → HAL。
反向通信只能通过：(1) 全局只读状态结构体；(2) 回调函数指针。

**为什么算法层不能碰 HAL**：`alg_bal` 将是本工程最需要反复迭代的部分，
放在纯函数层才能在 PC 上用 Python 对拍、用真实日志回放，换芯片也零改动。

## 3. 时间尺度（核心）

本工程有**三个时基**，互相解耦：

```
  20 kHz ─┬─ 50 µs ─┬─ 电流环（ADC 注入 → JEOC → FOC → CCR）
          │         │
   1 kHz ─┼─ 1 ms ──┼─ 轮速度环（ADC ISR 内 20 分频）【继承】
          │         │
  200 Hz ─┼─ 5 ms ──┼─ 姿态更新 + 平衡律（受 IMU 帧率限制）【新增】
          │         │
 主循环 ──┴─ 不定 ──┴─ 命令解析 / 日志 / 波形上报
```

**关键设计决定：平衡环不与电流环同频。**
动量轮电机的电气时间常数远小于机械/倒立摆时间常数，所以力矩指令按 200 Hz 更新、
由 20 kHz 电流环零阶保持执行即可——**平衡环的输出是"力矩（电流）指令"，不是占空比**。

### 3.1 20 kHz 电流环（【继承】，已实测）

```
TIM1 峰顶 → CH4 触发 ADC2 注入组(JEOC) → 读 3 路电流 + 角度 → Clarke/Park → PI → SVPWM → CCR
```

| 环节 | dsh_foc 实测 | 说明 |
|---|---|---|
| ADC 触发 → 中断入口 | 28.3 µs（周期内位置） | 硬件 |
| ISR 本体 | 2.37 µs | 含编码器 DMA 启动 |
| 编码器解码 | 3.18 µs | DMA 后台完成 |
| 控制链（Clarke→PI→SVPWM→CCR） | 6.5 µs | |
| 周期 | 50.0 µs | 20 kHz |

### 3.2 200 Hz 平衡环（【新增】）

| 项 | 值 | 说明 |
|---|---|---|
| 名义周期 | 5 ms | IMU 200 帧/s |
| 输入 | 俯仰角 θ、角速度 θ̇、轮速 ω | 全部带时间戳 |
| 输出 | 轮力矩指令（q 轴电流指令） | 交给 1 kHz/20 kHz 内环执行 |
| 单次预算 | **≤ 300 µs**（占 6%） | 含姿态解算与控制律 |

**触发方式待定**（见 [18_待确认清单.md](18_待确认清单.md) T16）：

- 方案 A（事件驱动）：USART1 IDLE 中断里直接算 → 与数据同步，但抖动来自串口
- 方案 B（固定定时器）：200 Hz 定时器中断里取"最新一帧"→ 周期严格，但有 0~5 ms 零阶保持误差

> 工作流 07 的要求：**判据优先选不依赖抖动的量**。若最终走 B，仿真里必须同样按零阶保持建模。

### 3.3 中断优先级（【继承】+ 新增 USART1）

`NVIC_PRIORITYGROUP_4`，数值越小优先级越高。

| 中断 | 抢占优先级 | 理由 |
|---|---|---|
| `ADC1_2_IRQn`（JEOC，20 kHz 电流环） | **0** | 硬实时，绝对最高 |
| `DMA1_Channel1/2_IRQn`（USART1 收发） | 2 | 不能挡住 FOC |
| `USART1_IRQn`（IDLE） | 3 | 只做"帧到达"标记 |
| `TIM6_IRQn`（200 Hz 平衡环，若用方案 B） | **1** | 高于串口、低于电流环 |
| `SysTick_IRQn` | 15 | HAL 时基 |

**ISR 纪律**：禁止 `printf`、`HAL_Delay`、动态内存、阻塞等待；允许读写寄存器、单精度浮点、置标志。

## 4. 状态机（【继承】+ 扩展 BAL）

```
        上电
         │
         ▼
   ┌─────────┐  自检通过   ┌────────┐  start    ┌────────┐
   │  INIT   │───────────▶│  IDLE  │──────────▶│ ALIGN  │
   └────┬────┘            └───┬────┘           └───┬────┘
        │ 自检失败             ▲                   │ 预定位完成
        ▼                     │                   ▼
   ┌─────────┐  清故障         │              ┌────────┐
   │  FAULT  │────────────────┘              │  RUN   │ 轮速/电流环
   └─────────┘                               └───┬────┘
        ▲                                        │ bal on（需姿态有效）
        │ 任意状态检测到故障                      ▼
        └──────────────────────────────────┌────────┐
                                           │  BAL   │ 平衡闭环
                                           └────────┘
                                    │ 倾角 > 25° / bal off
                                    ▼
                                 ┌────────┐
                                 │  IDLE  │（停轮，复位积分）
                                 └────────┘
```

| 状态 | 含义 | 允许的事件 |
|---|---|---|
| INIT | 外设自检、IMU 握手 | 自检通过 → IDLE；失败 → FAULT |
| IDLE | 封波待命 | start → ALIGN；bal on → 拒绝（姿态未就绪） |
| ALIGN | 固定 d 轴电流预定位 | 完成 → RUN |
| RUN | 轮速闭环 / 电流闭环 | bal on → BAL；stop → IDLE |
| BAL | 平衡闭环（外环） | bal off / 超角 → IDLE；故障 → FAULT |
| FAULT | `MOE=0` 封波，记录故障码 | 仅命令清除 → IDLE |

**硬性要求（工作流 07）**：状态切换必须有**结构性硬优先级**，setter 不得带启动副作用；
`bal on` 只有在"IMU 帧连续有效 + 轮速在量程内 + 倾角在捕获范围内"三条同时满足时才被接受。

## 5. 初始化顺序（main.c 的 USER CODE 段）

```
HAL_Init → SystemClock_Config → MX_GPIO/DMA/USART1/TIM1/SPI/ADC
  → app_init()
        ├─ bsp_gpio_init()            // PA0 上拉、LED 熄灭
        ├─ bsp_uart_init()            // 调试口（USART1 或 USART2，见 T2）
        ├─ bsp_imu_init()             // 【新增】IMU 串口 DMA + 波特率自检
        ├─ app_cmd_init()
        └─ banner + 状态进 IDLE
  → while(1) { app_loop(); }
```

**顺序红线（继承 dsh_foc 的教训）**：
1. ADC 校准必须在 PWM 输出**之前**完成，否则 INA240 零漂带开关噪声偏置；
2. 电流零漂校准必须在三相完全关断时做；
3. IMU 自检（200 帧/s、CRC 全对）必须在允许 `bal on` **之前**完成，否则平衡环会拿到陈旧姿态。

## 6. 目录与命名约定（【规划】）

```
User/
  Cfg/   board_cfg.h   板级常量（时钟/死区/采样电阻/分压/LED与KEY极性/缓冲大小）
         foc_cfg.h     电机与控制参数（极对数、R、L、PI、限幅、保护阈值）
         ctl_cfg.h     平衡参数（LQR 增益或 PID、倾角阈值、IMU 超时）
  Bsp/   bsp_gpio.c  bsp_uart.c  bsp_pwm.c  bsp_adc.c  bsp_prof.c
         bsp_flash.c  bsp_ssi.c（MT6701）  bsp_imu.c
  Mid/   mid_ringbuf.c  mid_log.c  mid_vofa.c  mid_current.c
         mid_angle.c  mid_fdilink.c  mid_att.c
  Alg/   alg_svpwm.c  alg_clarke.c  alg_park.c  alg_pi.c  alg_foc.c  alg_bal.c
  App/   app_main.c  app_state.c  app_cmd.c  app_balance.c
```

**约定**：
- 文件名前缀 = 所属层（`bsp_` / `mid_` / `alg_` / `app_`），函数名与文件名一致；
- 宏全大写下划线，**代码里不允许出现魔法数字**；
- **源码必须纯 ASCII**（注释与字符串用英文）；中文一律写进 `docs/`；
- 每个 `.h` 用 `extern "C"` 包裹，便于 PC 仿真；
- CubeMX 生成的 `.c` 只在 `USER CODE BEGIN/END` 之间改动。

## 10. 已知限制

- 平衡环受 IMU 200 帧/s 限制，理论最小相位滞后 2.5 ms（半拍），等效相位损失随带宽上升而恶化（见 18#T9）。
- 电流量程 ±1.32 A，若动量轮惯量不足需要更大加速度，会先撞电流饱和（见 18#T3）。
- 单 UART 冲突：USART1 同时被 IMU 与调试台需要（见 18#T2）。
