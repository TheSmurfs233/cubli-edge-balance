# 主框架

> 代码位置：`User/`（**S0 尚未创建 Keil 工程**）
> 本文是整套工程的"总图"：**分层、时序、优先级、状态机、目录约定以本文为准**。
> 标注说明：**【继承】**= 来自 `dsh_foc` 已验收代码；**【新增】**= 本工程要写；**【规划】**= 尚未实现。

## 1. 职责边界

主框架不实现控制算法，只定义：

- 代码分层与依赖方向（谁能调谁）
- 三个时基（20 kHz / 1 kHz / 200 Hz）的**分工与时间预算**
- 中断优先级分配
- 全局状态机与初始化顺序
- 目录与命名约定

**不负责**：FOC 数学（见 `workflow` 与本工程后续 1x 子文档）、IMU 协议解析、平衡律整定。

**依赖方向严格单向向下**：App → Alg → Mid → Bsp → HAL。
反向通信只能通过：(1) 全局只读状态结构体；(2) 回调函数指针。

**为什么算法层不能碰 HAL**：`alg_bal` 将是本工程最需要反复迭代的部分，
放在纯函数层才能在 PC 上用 Python 对拍、用真实日志回放，换芯片也零改动。

## 3. 时间尺度（核心）

本工程有**三个时基**，互相解耦：

```
  20 kHz ─┬─ 50 µs ─┬─ 电流环（ADC 注入 → JEOC → FOC → CCR）
          │         │
   1 kHz ─┼─ 1 ms ──┼─ 轮速度环（ADC ISR 内 20 分频）【继承】
          │         │
  200 Hz ─┼── 5 ms ─┼─ 姿态更新 + 平衡律（模块 `0x41` 已提到 200 Hz，见 `18#T18`）【新增】
          │         │
 主循环 ──┴─ 不定 ──┴─ 命令解析 / 日志 / 波形上报
```

**关键设计决定：平衡环不与电流环同频。**
动量轮电机的电气时间常数远小于机械/倒立摆时间常数，所以力矩指令按 200 Hz 更新、
由 20 kHz 电流环零阶保持执行即可——**平衡环的输出是"力矩（电流）指令"，不是占空比**。

### 3.1 20 kHz 电流环（【继承】，已实测）

```
TIM1 峰顶 → CH4 触发 ADC2 注入组(JEOC) → 读 3 路电流 + 角度 → Clarke/Park → PI → SVPWM → CCR
```

| 环节 | dsh_foc 实测 | 说明 |
|---|---|---|
| ADC 触发 → 中断入口 | 28.3 µs（周期内位置） | 硬件 |
| ISR 本体 | 2.37 µs | 含编码器 DMA 启动 |
| 编码器解码 | 3.18 µs | DMA 后台完成 |
| 控制链（Clarke→PI→SVPWM→CCR） | 6.5 µs | |
| 周期 | 50.0 µs | 20 kHz |

### 3.2 200 Hz 平衡环（【新增】）

| 项 | 值 | 说明 |
|---|---|---|
| 名义周期 | **5 ms** | 姿态 `0x41` 已由 `imu rate 200` 提到 200 Hz（实测 199.78 帧/s，`00` #012、`90` L-1、`18#T18`） |
| 输入 | 俯仰角 θ、角速度 θ̇、轮速 ω | 全部带时间戳 |
| 输出 | 轮力矩指令（q 轴电流指令） | 交给 1 kHz/20 kHz 内环执行 |
| 单次预算 | **≤ 300 µs**（占 6%） | 含姿态解算与控制律 |

**触发方式待定**（见 [18_待确认清单.md](18_待确认清单.md) T16）：

- 方案 A（事件驱动）：USART1 IDLE 中断里直接算 → 与数据同步，但抖动来自串口
- 方案 B（固定定时器）：200 Hz 定时器中断里取"最新一帧"→ 周期严格，但有 0~5 ms 零阶保持误差（**已选定**，`18#T16`）

> 工作流 07 的要求：**判据优先选不依赖抖动的量**。若最终走 B，仿真里必须同样按零阶保持建模。

### 3.3 中断优先级（【继承】+ 新增 USART1）

`NVIC_PRIORITYGROUP_4`，数值越小优先级越高。

| 中断 | 抢占优先级 | 理由 |
|---|---|---|
| `ADC1_2_IRQn`（JEOC，20 kHz 电流环） | **0** | 硬实时，绝对最高 |
| `TIM6_IRQn`（200 Hz 平衡环） | **1** | 高于串口、低于电流环 |
| `DMA1_Channel1/2/3/4/5_IRQn`（USART1/2、SPI1 收发） | 2 | 不能挡住 FOC |
| `USART1_IRQn`（IMU 帧 IDLE） | 3 | 只做"帧到达"标记 |
| `USART2_IRQn`（调试口 IDLE） | 4 | 纯人机交互，最不重要 |
| `SysTick_IRQn` | 15 | HAL 时基 |

**ISR 纪律**：禁止 `printf`、`HAL_Delay`、动态内存、阻塞等待；允许读写寄存器、单精度浮点、置标志。

## 4. 状态机（【继承】+ 扩展 BAL）

```
        上电
         │
         ▼
   ┌─────────┐  自检通过   ┌────────┐  start    ┌────────┐
   │  INIT   │───────────▶│  IDLE  │──────────▶│ ALIGN  │
   └────┬────┘            └───┬────┘           └───┬────┘
        │ 自检失败             ▲                   │ 预定位完成
        ▼                     │                   ▼
   ┌─────────┐  清故障         │              ┌────────┐
   │  FAULT  │────────────────┘              │  RUN   │ 轮速/电流环
   └─────────┘                               └───┬────┘
        ▲                                        │ bal on（需姿态有效）
        │ 任意状态检测到故障                      ▼
        └──────────────────────────────────┌────────┐
                                           │  BAL   │ 平衡闭环
                                           └────────┘
                                    │ 倾角 > 25° / bal off
                                    ▼
                                 ┌────────┐
                                 │  IDLE  │（停轮，复位积分）
                                 └────────┘
```

| 状态 | 含义 | 允许的事件 |
|---|---|---|
| INIT | 外设自检、IMU 握手 | 自检通过 → IDLE；失败 → FAULT |
| IDLE | 封波待命 | start → ALIGN；bal on → 拒绝（姿态未就绪） |
| ALIGN | 固定 d 轴电流预定位 | 完成 → RUN |
| RUN | 轮速闭环 / 电流闭环 | bal on → BAL；stop → IDLE |
| BAL | 平衡闭环（外环） | bal off / 超角 → IDLE；故障 → FAULT |
| FAULT | `MOE=0` 封波，记录故障码 | 仅命令清除 → IDLE |

**硬性要求（工作流 07）**：状态切换必须有**结构性硬优先级**，setter 不得带启动副作用；
`bal on` 只有在"IMU 帧连续有效 + 轮速在量程内 + 倾角在捕获范围内"三条同时满足时才被接受。

## 5. 初始化顺序（main.c 的 USER CODE 段）

> 端口分配已定（`18#T2`）：**USART1 = IMU（921600）**，**USART2 = 调试命令台（1 Mbaud，CH340N）**。
> 实物端口：**COM7 = USART1，插上 IMU 后这条 USB 连接就不可再用于调试**；调试、日志与 VOFA+ 波形一律走 **COM13 = USART2**。
> 因此 `bsp_uart` 必须句柄参数化，两路各自独立的环形缓冲与回调。

```
HAL_Init → SystemClock_Config → MX_GPIO/DMA/USART1/USART2/TIM1/SPI/ADC
  → app_init()
        ├─ bsp_gpio_init()            // PA0 上拉、LED 熄灭
        ├─ bsp_uart_init()            // USART2 调试口（DMA1_CH3/CH4）
        ├─ imu_init()                 // 【步骤6 落地】USART1 IMU 口（RX=DMA1_CH1 环形）
        ├─ bsp_pwm_init()
        ├─ mid_current_init() / bsp_adc_init()
        ├─ app_cmd_init()
        └─ banner（含 imu 行）+ 状态进 IDLE
  → while(1) { app_loop(); }     // 内含 imu_poll()，紧跟 bsp_uart_tx_pump()
```

**顺序红线（继承 dsh_foc 的教训）**：
1. ADC 校准必须在 PWM 输出**之前**完成，否则 INA240 零漂带开关噪声偏置；
2. 电流零漂校准必须在三相完全关断时做；
3. IMU 自检（姿态 200 Hz、CRC 全对）必须在允许 `bal on` **之前**完成，否则平衡环会拿到陈旧姿态。

## 9. 验证方法

| 层 | 验证方式 |
|---|---|
| Alg | PC 上固定输入输出对拍（Clarke/Park/SVPWM/平衡律），Python 独立实现同一公式比对 |
| Mid | 主机测试喂真实抓包数据（IMU 帧、编码器帧），断言解析结果 |
| Bsp | 每个 bsp 模块一个自检函数，串口打印 `bsp_xxx OK`/失败码；**启动横幅在自检失败时追加告警文本**（如 `(DMA CH MISMATCH, SPI DISABLED)`） |
| 跨文件绑定 | `python test/check_binding.py`：DMA 通道号、串口实例、波特率、RX 环形 DMA 模式、ASCII 纯度共 11 项静态检查，退出码 0 才算过 |
| Mid/Alg（纯算法） | `bash test/l1/run.sh`：把 `User/Mid/*.c`、`User/Alg/alg_bal.c` 原样拿到 PC 上用 gcc 编译，喂合成输入对拍（`mid_fdilink` 覆盖 CRC8/CRC16/尾字节/重同步/分包等价/序号跳变，15 项；`mid_att` 覆盖零位/符号/限幅边界/帧龄/不均间隔/低通/时间戳回绕，12 例；`alg_bal` 覆盖三项增益/符号/死区/饱和/非法调参 + 3 条 python 金标值，15 例 17 检查） |
| 主框架 | GPIO 翻转 + 示波器测各回路执行时间；`wave` 统计 200 Hz 实际周期与抖动 |
| L2 主机测试 | `bash test/host/build.sh`：WSL gcc + `test/host/fake/` 的假 HAL 跑真实固件源码（`app_main`/`app_cmd`/`bsp_uart`/`bsp_imu`/`mid_*`/`alg_*`），633 项断言；IMU 用 `fake_imu_rx_feed()` 注入合成 FDILink 帧，TX 用 `fake_imu_tx_*` 检查 |
| 一键复现 | `bash test/verify.sh`：绑定 → L1 → L2 → 文档四道门依次跑，任一红即退出码 1；固件 Keil 构建是 Windows 独有门禁，需单独跑 |

> 主机测试的 fake HAL 有**两个 UART**（USART1 = IMU、USART2 = 调试），TX 捕获与 RX 注入都按句柄分派。
> 旧版 fake 写死 `&huart1`，在双口工程里会把 IMU 的发送完成回调算到调试口头上（`docs/00_开发日志.md` #010）。

> `check_binding.py` 的由来：`bsp_ssi.c` 从 dsh_foc 继承时把 SPI1_RX 的 DMA 写死成 CH3，
> 而本工程在 CH5。编译 0E0W 完全不受影响，上板表现为编码器读数不动而 CRC 仍正确（`docs/00_开发日志.md` #008）。
> 凡是"照着别的工程抄过来、又依赖 CubeMX 分配结果"的常量，都归这一层检查。

> **编码器一次读 32 位，不是 24 位**（`BSP_SSI_FRAME_LEN 4u`，`docs/00_开发日志.md` #052）：MT6701 没有帧同步，
> 一次传输被打断后读者会整体偏一个字节，且 `bsp_ssi_abort()` 只会让它锁死在一个错相位上。多读一个字节后，
> `mid_enc` 在 9 个 24 位窗口里按 CRC6 找正帧，并用"角度连续"门拒绝 CRC 侥幸命中。代价是 SPI 移位 2.26 µs → 3.01 µs，
> CPU 多一次哑字节的 TXE 等待（≈0.75 µs），`prof` 的 `enc` 槽仍是 50 µs 周期里的个位数微秒。
> 另外每帧处理完立即装下一帧，RUN 下才是真的 20 kHz（此前只在"未就绪"分支装帧，最多 10 kHz）。

## 10. 已知限制

- 平衡环名义周期 5 ms（姿态 `0x41` 已提到 200 Hz）；理论最小相位滞后 2.5 ms（半拍）。
  模块的**单包速率上限就是 200 Hz**，再提要走自己的融合（见 18#T9/T18、90 号 L-1/L-1b/L-9）。
- **力矩余量受电流量程锁死**：`Kt = 0.0289 N·m/A`（7 极对、KV 330），`I_MAX = 1.2 A` → 最大反作用力矩 **34.7 mN·m**。
  倒立摆保持需要 `m·g·h·sinθ`，10 cm / 1 kg 立方体在 ±3° 就要 25.7 mN·m，±5° 需要 42.8 mN·m → **做不出来**（见 18#T17、90 号 L-8）。
- DMA 通道号是"照着别的工程抄、又依赖 CubeMX 分配"的易错项，已由 `test/check_binding.py` 静态兜底（见 §9）。
