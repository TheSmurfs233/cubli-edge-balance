## 1. 整机拓扑（本版）

```
        ┌──────────────────────────────┐
        │  STM32G431（单板，主控+FOC）  │
        │                              │
  IMU ──┤ USART1 PB6/PB7  921600 bps  │
 N100   │        ↑ 姿态 100 Hz         │
 Mini   │                              │
        │ TIM1 ──► EG3033 ──► AO4606 ──┼──► 动量轮电机（三相）
        │ ADC2 ◄── INA240A2 ×3 (25mΩ)  │
        │ SPI1 ◄── MT6701（轮轴角度）   │
        │ USART2 ── CH340N ── USB-C    │──► 调试（可选）
        └──────────────────────────────┘
                    ▲
                 DC_BUS 12 V
```

**只有一台电机、一个动量轮。** 三个轮的点平衡不在本版范围内（见 02 需求规格 N-1）。

## 5. 对外连接

| 接口 | 引脚 | 连接器 | PC 侧端口 | 用途 |
|---|---|---|---|---|
| USART1 | PB6/PB7 | CN3（WAFER-SH1.0-**6P**） | 经 USB-TTL 转接 = **COM7** | **IMU（N100 Mini）@921600**，已定（18#T2） |
| USART2 | PA2/PA3 | 板载 CH340N → USB Type-C | **COM13** | **调试命令台 + 日志 + VOFA+ 波形 @1 Mbaud** |
| SPI1 | PB3/PB4/PB5 + PA15 | MT6701 模块 | — | 轮轴角度 |
| SWD | PA13/PA14 | H1 排针 | — | 下载/调试 |
| DC_BUS | — | 接线端子 | — | 12 V 输入 |

### 端口切换的实际后果（关键）

**COM7（USART1）一旦插上 IMU 就被占用，这个 USB 连接随即不可用于调试。**
此后所有 `help`/`stat`/`ver` 命令与 VOFA+ 波形**必须走 COM13（USART2）**。

> 这条决定了 `bsp_uart` 必须句柄参数化：调试台绑 USART2，IMU 绑 USART1，两者不能共用一套字节流。
> 端口号由操作系统分配，可能变化——**认"板载 CH340N 的 USB 设备"而不是认 COM13 这个数字**。

⚠ **CN3 是 1.0 mm 间距的 6P 排针**，接 IMU 需要 1.0 mm 转 2.54 mm 的转接线或转接板（见 18#T13）。

## 6. IMU 链路（N100 Mini）

| 项 | 值 |
|---|---|
| 模块 | WHEELTEC N100 Mini 九轴 AHRS（无气压计） |
| 协议 | FDILink V21.0823，帧头 0x40（IMU）/ 0x41（AHRS） |
| 波特率 | 921600（8N1） |
| 输出速率 | **现状：姿态 `0x41` 200 Hz、原始 `0x40` 100 Hz，合计 300 包/s、17.6 kB/s**（2026-11-04 实测 199.78 / 99.89 帧/s，见 `00` #012）。出厂默认是两包各 100 Hz；单包速率**上限 200 Hz** |
| 速率配置 | 固件命令 `imu rate <hz> [save]`（内部走模块 ASCII 配置口 `#fconfig` → `#fmsg 41 <hz>` → `#fsave` → `#freboot` → `#fdeconfig`，时序要求极严，见 `90` L-9） |
| 校验 | CRC 全对，已上板验证；支持热插拔恢复 |
| 本工程实现 | `User/Bsp/bsp_imu.c/h`（串口/DMA/缓冲）+ `User/Mid/mid_fdilink.c/h`（纯协议解析，无 HAL），S1 步骤6 移植 |
| 接收通道 | USART1_RX = `DMA1_Channel1`，`DMA_CIRCULAR` + `HAL_UARTEx_ReceiveToIdle_DMA` |
| 发送通道 | USART1_TX = `DMA1_Channel2`，但本工程用 `HAL_UART_Transmit_IT`（配置命令很短，无需 DMA） |
| 回调分发 | `HAL_UART*Callback` 由 `User/Bsp/bsp_uart.c` 按 `huart->Instance` 分发：USART1 → `imu_uart_*_isr()`，USART2 → 调试口 |
| 参考实现 | `D:\Embedded\STM32\gyroscope`（原始版本，DMA 用的是 CH3，本工程必须用 CH1） |
| 坐标系 | 模块丝印方向，与立方体坐标系的对应关系见 18#T6 |

## 7. 资源占用（基线参考）

| 工程 | Flash（Code+RO） | RAM（RW+ZI） | 说明 |
|---|---|---|---|
| `dsh_foc` #173 | 64658 + 2546 = **67.2 KB** | 496 + 10048 = **10.3 KB** | 含无感 FOC（S10），2026-11-03 复现一致 |
| `gyroscope` | 22734 + 1102 = **23.8 KB** | 120 + 13096 = **12.9 KB** | 含 HAL + IMU |
| **`cubli` S1 步骤4** | 64406 + 2546 = **66.9 KB** | 496 + 10384 = **10.6 KB** | 已接回 `app_init`/`app_loop`，含 USART2 |
| **`cubli` S1 步骤5** | 64626 + 2546 = **67.2 KB** | 496 + 10384 = **10.6 KB** | 调试口切 USART2、修 SPI1_RX 的 DMA 通道 |
| **`cubli` S1 步骤6** | 67870 + 2810 = **70.7 KB** | 536 + 14352 = **14.9 KB** | 加 IMU（`bsp_imu` + `mid_fdilink` + `imu` 命令），Flash 占用 54%、RAM 47% |
| 合并估算（加 IMU） | **≈77~80 KB** | **≈22 KB** | 两者共享 HAL/启动代码，直接相加偏大 |

- 相对基线：Code **−252 B**、RO 相同、RW 相同、ZI **+336 B**（`huart2` 与 `hdma_usart2_rx/tx` 句柄）。
  −252 B 未逐项解释（同源码同编译器 ARMCC V5.06u5，已用 `dsh_foc` 复现基线数字确认不是环境差异），
  量级 0.4%，登记为观察项，不阻塞。
- 栈 `Stack_Size=0x800`（CubeMX 默认 `0x400`）：基线 `dsh_foc` 的 11 号文档实测 `printf` + 浮点格式化可能吃掉 500 B+ 栈，
  出现异常复位应优先怀疑栈溢出。本工程沿用同一 `app_main` 的日志路径，故同样放大到 0x800。

结论：**64 KB Flash 的 K8 装不下**，需 128 KB 的 KB 或大幅裁剪（见 [90_已知问题与限制.md](90_已知问题与限制.md) L-1、18#T1）。

## 9. DMA 通道分配（通道号与 `dsh_foc` 有差异，见下）

| 通道 | 用途 | 流优先级 | 中断 |
|---|---|---|---|
| DMA1_Channel1 | USART1_RX（IMU，环形缓冲） | LOW | 用 |
| DMA1_Channel2 | USART1_TX | LOW | 用 |
| DMA1_Channel3 | **USART2_RX（调试口）** | LOW | 用 |
| DMA1_Channel4 | **USART2_TX（调试口）** | LOW | 用 |
| DMA1_Channel5 | SPI1_RX（MT6701） | **VERY_HIGH** | 不用（轮询 TC） |
| DMA1_Channel6 | 空闲 | — | — |

> **流优先级只有编码器（CH5）是 `VERY_HIGH`**：MT6701 每 50 µs 采一次角度，电流环等不起；
> 三个串口通道全部降为 `LOW`（IMU 仅 2 KB/s，调试口是人机交互），避免它们与编码器抢仲裁。

> **与 `dsh_foc` 的差异**：G431 的 DMA1 只有 CH1~CH6（**没有 CH7**），带 DMAMUX，任意通道可映射任意请求。
> `dsh_foc` 里 SPI1_RX 用 CH3；本工程加 USART2 后 CubeMX 把 SPI1_RX 自动挪到 **CH5**，CH3/CH4 归 USART2。
> 移植 `dsh_foc` 代码时**只认句柄名**（`hdma_spi1_rx` 等），不要认通道号。

> **已实测踩坑（S1 步骤 5，`docs/00_开发日志.md` #008）**：`bsp_ssi.c` 从 `dsh_foc` 继承时把通道号写死成 CH3，
> 而本工程是 CH5 —— 编译 0E0W 毫无提示，上板会表现为"编码器读数不动、CRC 却全对"。
> 现已改为宏 + 运行期句柄校验（`bsp_ssi_cfg_error()`），并由 `test/check_binding.py` 第 1/2 项静态兜底。
> 上表通道号已与 `Core/Src/spi.c`、`Core/Src/usart.c` 的实际句柄逐一核对。
