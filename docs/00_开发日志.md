## 2026-11-03 #001 工具链摸底：WSL 不可用于 L1 仿真，改用 Windows uv 环境

### 背景
`workflow/04_仿真先行.md` 要求 L1 离线算法仿真跑在 WSL（Python/Octave）。开工前先验证 WSL 是否具备 numpy/scipy。

2. `pip install numpy` 与清华/阿里/中科大镜像全部超时；`getent hosts pypi.org` 返回 `198.18.0.47`（fake-ip 段，说明 DNS 被宿主代理劫持）。

### 数据
| 项 | WSL Ubuntu-24.04 | Windows |
|---|---|---|
| Python | 3.12.3 | 3.12.14 / 3.11.15 |
| numpy | ❌ | ✅ 2.5.4（uv 环境） |

| 结论 | 与手算一致，环境可用 |

### 结论与动作
1. **L1 仿真改在 `D:\Embedded\STM32\cubli\.tmp_env\venv`（uv 创建）里跑**，numpy/scipy/control/matplotlib 齐全。
2. 仿真脚本仍按 POSIX 路径与 `#!/usr/bin/env python3` 写，将来 WSL 若通网可原样搬回，不重写。
3. 硬件在环（L3）本来就在 Windows 侧（串口），不受影响。
4. `.tmp_env/` 加入 `.gitignore`，不提交。

## 2026-11-03 #004 S1 步骤1：CubeMX 工程生成与 4 项配置纠偏

### 背景

## 2026-11-03 #005 USART1 的 DMA 流优先级降到 LOW

### 背景
#004 遗留项：`hdma_usart1_rx/tx` 的流优先级是 `VERY_HIGH`，与编码器 `hdma_spi1_rx` 相同，两者会争 DMA 仲裁。

### 现象 / 问题
IMU 只有 2 KB/s（5 ms 一帧），调试口是人机交互；而 MT6701 每 50 µs 就要一次角度给 20 kHz 电流环用。
四方（USART1×2、USART2×2）与编码器在 DMA1 上抢同一条总线时，`VERY_HIGH` 的串口通道会先占用总线。

### 动作
用户在 CubeMX 的 USART1 → DMA Settings 把两个通道的 Priority 改为 `Low` 并重新生成。

### 数据
改动范围（`git diff` 逐行确认，**只有这两处，无其它副作用**）：

| 文件 | 改动 |
|---|---|
| `Core\Src\usart.c:168` | `hdma_usart1_rx.Init.Priority`: `VERY_HIGH` → `LOW` |
| `Core\Src\usart.c:185` | `hdma_usart1_tx.Init.Priority`: `VERY_HIGH` → `LOW` |
| `cubli.ioc` | `Dma.USART1_RX.0.Priority`、`Dma.USART1_TX.1.Priority` 同步为 `DMA_PRIORITY_LOW` |

改后五个通道的流优先级：

| 通道 | 用途 | 优先级 |
|---|---|---|
| DMA1_CH1 / CH2 | USART1 RX/TX（IMU） | LOW |
| DMA1_CH3 / CH4 | USART2 RX/TX（调试） | LOW |
| DMA1_CH5 | SPI1 RX（MT6701 编码器） | **VERY_HIGH** |

### 结论
现在只有编码器拿最高流优先级，与"电流环 20 kHz 等不起"的事实一致。

- [x] `.c` 与 `.ioc` 双向一致（三个文件项全部同步）
- [x] `git diff --stat` 仅 2 文件 4 行，无意外改动
- [x] 增量编译 `-b`：0E / 0W（`build_s1_step1_f.log`，18 s）

## 2026-11-03 #008 S1 步骤5：调试口切到 USART2，并修掉一个编译发现不了的 DMA 通道 bug

### 背景
S1 步骤 5 的目标是让 `bsp_uart` 从驱动 USART1 改成驱动 USART2（PA2/PA3 + 板载 CH340N → USB Type-C），
因为 USART1（PB6/PB7 → CN3）已经指定给 N100 Mini IMU。用户同时指示"电机相关的数据参考 dsh_foc 工程"。

### 现象 / 问题
1. `User/Bsp/bsp_uart.c` 里 `huart1` 出现 4 次、`huart->Instance != USART1` 判断 3 次，还有一句
   `extern DMA_HandleTypeDef hdma_usart1_rx;` 从未被使用——换口必须把这层写死的东西全部拆掉。
2. **`User/Bsp/bsp_ssi.c` 把 SPI1_RX 的 DMA 通道写死成 DMA1_Channel3**：
   `#define SSI_DMA DMA1_Channel3`、`DMA1->IFCR = DMA_IFCR_CGIF3`、`DMA1->ISR & DMA_ISR_TCIF3`。
   而本工程 CubeMX 把 SPI1_RX 放在 **DMA1_Channel5**（`Core/Src/spi.c:92`
   `hdma_spi1_rx.Instance = DMA1_Channel5;`，请求 `DMA_REQUEST_SPI1_RX`），CH3 让给了 USART2_RX。
   后果：`bsp_ssi` 轮询的是 CH3 的 TC 标志，而 CH3 属于串口、永远不会有 SPI 的传输完成 →
   **编码器读到的是陈旧字节，但 CRC 依然是对的**，编译 0E0W、任何静态检查都发现不了。
   这正是"能编译"与"能做对"之间的缝隙（工作流 03 的核心提醒）。

### 动作
| 文件 | 改动 |
|---|---|
| `User/Bsp/bsp_ssi.c` | `SSI_DMA`→`DMA1_Channel5`、`SSI_IFCR_CGIF`→`DMA_IFCR_CGIF5`、`SSI_ISR_TCIF`→`DMA_ISR_TCIF5`，字面量全部换成宏；`bsp_ssi_init()` 增加句柄自检 `if ((hspi1.hdmarx == 0) \|\| (hspi1.hdmarx->Instance != SSI_DMA)) { s_cfg_err = 1u; return; }`，通道不符就完全不碰总线；`bsp_ssi_start()` 开头 `if (s_cfg_err != 0u) return;`；新增 `bsp_ssi_cfg_error()` |
| `User/Bsp/bsp_uart.c` | 全文 `huart1`→`huart2`、`USART1`→`USART2`；删除未使用的 `extern hdma_usart1_rx`；注释改为 `USART2(PA3) -> DMA1_CH3 (CIRCULAR)` / `DMA1_CH4 (NORMAL) -> USART2(PA2)`；新增 3 个配置位掩码自检（波特率 / 无 DMA 句柄 / RX 非 CIRCULAR）与 `bsp_uart_cfg_error()` |

| `test/check_binding.py` | **新建**：7 项跨文件绑定检查，见下 |

`test/check_binding.py`（Python 3 标准库，154 行，全 PASS 才 exit 0）：
1. `bsp_ssi.c` 的 `SSI_DMA` 与 `spi.c` 的 `hdma_spi1_rx.Instance` 必须同通道；
2. `SSI_IFCR_CGIF` / `SSI_ISR_TCIF` 的编号必须随该通道；
3. `bsp_uart.c` 必须驱动 USART2，且全文不得出现 `huart1` / `USART1`；

4. **`verify.sh` 的价值在"顺序"**：绑定检查最便宜（毫秒级），先跑；L2 最贵（秒级），中间；文档检查最后。

## #019 S3 上板：力矩线性、饱和边界、轮惯量 J 与摩擦

- 日期：2026-11-04
- 固件：`build = Nov  4 2026 20;29;20 #1`（Code=72860）
- 目的：验证 `docs/43` 的 A-2（力矩指令可用）、A-3（分辨率线性）、A-5（轮惯量 J）

### 现象 / 数据

**1. 力矩 -> 电流（`mode 2` + `start` 后逐档给，每档读 `torque`）**

| 指令 mN.m | iq_ref A | iq_meas A | 轮速 rpm | 判定 |

**2. 轮惯量（从静止给恒力矩，`torque` 轮询每 125 ms 一次）**

| 指令 | iq A | 斜率 rpm/s | alpha rad/s^2 | J_raw = tau/alpha |
|---|---|---|---|---|
| 10 | 0.348 | 1496 | 156.7 | 6.43e-5 |
| 20 | 0.682 | 3297 | 345.3 | 5.71e-5 |
| 30 | 1.040 | 5222 | 546.8 | 5.50e-5 |

（20 与 30 mN.m 档末段轮速过 1700 rpm 后 iq 掉到 0.25 A，拟合只取线性段。）

### 分析

1. 低速段（< 900 rpm）指令电流与实际电流一致到 1.5% 以内，
   `tau = Kt * iq`（Kt = 0.02891 N.m/A）这条换算链成立 -> **A-2、A-3 通过**。
2. 30/34 mN.m 档的电流缺口不是控制问题：轮速 1700 rpm 时反电动势约 5.15 V，
   母线 12 V 经调制后只剩 0.55 V 给 `iq * R`，所以 iq 只能到 0.4 A 左右。
   已登记 `90#L-12`。
3. `J_raw` 随手力矩增大而下降，说明有恒定摩擦。用 10 与 20 两档联立
   `tau - tauf = J * alpha` 解得 **J = 5.12e-5 kg.m^2、tauf = 2.05 mN.m**。
4. 互证：用这组数预测 30 mN.m 档 alpha = 547.1 rad/s^2，实测 546.8，差 0.05%
   -> **A-5 通过**，且模型 `tau = J*alpha + tauf` 在 150~550 rad/s^2 范围内可信。
5. J 只有 5.1e-5（远小于电机手册里的 9e-5 那个"转子 + 台架负载"），
   意味着 34 mN.m 能给到约 660 rad/s^2：**平衡时轮速必须压在 +-500 rpm 内**，
   否则电压饱和会让指令力矩名不副实。

### 结论与动作

- S3 的 A-1/A-2/A-3/A-5 已由实测覆盖；A-4（反作用符号定 `ATT_SIGN`）未做。

## #021 S4 设计仿真的代码审查：修掉 4 个仿真缺陷

- 日期：2026-11-04
- 阶段：S4
- 关联：`docs/44_阶段方案_S4.md`、`sim/s4_design.py`、`docs/18` T20

### 背景

用户问“有没有实现仿真、仿真怎么样”，并要求“再检查一下有没有问题”。`sim/s4_design.py`
当时还没入库（`git ls-files sim` 为空），属于“文档引用了不存在的证据”的情况，必须先审查再提交。

### 现象 / 问题（4 条，全部是仿真代码自身的缺陷）

| # | 问题 | 后果 |
|---|---|---|
| 1 | 摩擦项写成 `fr = TAU_FRIC*sign(w) if tau != 0.0 else 0.0` | 指令被 `TAU_MIN` 抹零时摩擦同时消失，轮子无阻尼滑行，物理上不存在 |
| 2 | 完全没有静摩擦模型 | 库仑模型下轮速必停在 `τf/kw`，看起来像“物理必然”，实际是模型缺项 |
| 3 | 延迟缓冲 `append` 后无条件 `pop(0)` | `delay_steps=0` 也有 1 拍（5 ms）延迟，即“0 ms”档实际是 5 ms |
| 4 | `design_lqr()` 只返回 `-k[0]`，`KP/KD/KW` 是手抄的常量 | 改 `u0` 或改惯量时，文档里的增益与求解结果可能悄悄脱钩，没有任何断言 |

另外发现：4 状态预研里积分限幅写的是 `z_max = 0.05 rad`，而 `ki·z` 要顶住 2.05 mN·m 摩擦需要
`z ≈ 205 rad`，限幅把积分功能整个废掉了（第一版“轮速回到 −14 rpm”的结论不可复现）。

### 修法

1. 摩擦恒生效；新增静摩擦判据 `|ω| < OMEGA_STICK(0.5 rad/s) 且 |τ| ≤ τf` → 轮子锁死
   （`ω̇=0`，`fr=τ`，机体+轮整体按 `I+J` 做刚体运动）；
2. 延迟改为 `pop(0) if len(buf) > delay_steps else 0.0`；
3. `design_lqr()` 返回完整增益向量，`main()` 里断言“手抄值 == 求解值”，不一致就打印
   `NO -- docs/44 is out of date`；
4. `simulate()` 增加可选 `ki`、`z_max=400 rad` 参数（`ki=0` 即 S4 三状态），
   4 状态预研从此可用同一份代码复现。

### 数据（修正模型后重跑）

| 工况 | 修正前 | 修正后 |
|---|---|---|
| 3° 释放回 0.3° 内 | 4.38 s | **0.40 s** |
| 4.5° 释放 | 5.58 s | 2.17 s |
| 5.0° 释放 | FALL | FALL |
| 末端轮速 | −590 rpm | **+388 rpm** |
| 延迟 0/5/10/20 ms | 4.38~5.01 s | 0.38~0.40 s |

388 rpm 与解析值 490 rpm 的差值已定位：陀螺零偏 0.25 °/s 经 `kd` 贡献 `0.42 mN·m` 常值力矩，
抵掉了一部分摩擦。也就是说稳态轮速是摩擦与零偏的**合力结果**，不是常数。

### 4 状态（`18#T20`）复算结论修正

修正模型后，加 ω 积分确实能把轮速拉到 0 附近，但代价是**长周期极限环**：
60 s 窗口内 φ 摆 ±0.46°、轮速摆 ±600 rpm、周期 ~20 s。机理：轮子被静摩擦锁死后，
电机力矩不再传到机体，机体短暂失去控制量，一解列就是一次力矩冲击，积分器反复过冲。

1. **符号判据**：若 `ATT_SIGN` 反了，闭环时间常数约 0.13 s（7.5 rad/s），3 s 内必定

2. **轮速为何持续上涨**（不是失稳）：零点差 0.5 度需要约 2.9 mN.m 的常值力矩，

## #038 S6b 尝试：运行窗口放到 60 s，改拔线盲跑，被电池欠压挡住

**日期**：2026-11-05
**阶段**：S6（闭环）

### 背景

三次满窗实验（#037）都只跑到 14 s 左右，轮速以 85~105 rpm/s 单向累积，
按 `J·α + τf` 反推常值力矩只需 2.56 mN·m（等效零点偏差 0.45°）。
但 `omega_ss = C/kw` 的结构决定：这段常值力矩只能通过轮速来"兑换"，
所以 ~20 s 必然撞 1700 rpm 跳闸线。要够到 S6b 的 60 s 判据，先要弄清 C 从哪来。

### 现象

**1. trim 补偿无效**

| 运行 | trim | 窗口 | 饱和帧 | phi 峰 | 轮速峰 |
|---|---|---|---|---|---|
| 基准 | 0.00° | 14645 ms | 61 / 4400 | 2.29° | 1327 rpm |
| 补偿 | +0.35° | 15001 ms | 33 / 4507 | 2.49° | **1438 rpm** |

补偿后轮速反而更高，说明零点偏差不是主因。

**2. 仿真发现 C ≈ 15 mN·m 来自线缆**

新脚本 `sim/s6_kw_step.py`（`ext_mnm = 15`，ceiling 28，trip 1700）：

| 候选 | kp | kd | kw | 稳态轮速 | 捕获窗 |
|---|---|---|---|---|---|
| sigma 50 rpm（当前） | 1.3138 | 0.17552 | 3.8197e-4 | **1480 rpm** | 2°/3° ok，4° 倒 |
| sigma 20 rpm | 2.2979 | 0.30731 | 9.5493e-4 | 1036 rpm | 同上 |
| sigma 10 rpm | 3.9392 | 0.52711 | 1.9099e-3 | 888 rpm | 同上 |

稳态轮速 1480 rpm 与实测 1327 rpm 同量级，证明"线缆常值力矩"是主因；
**提高 kw 只有 30% 收益，捕获窗一点没变**——只要线还在拉，轮速迟早撞线。

### 分析

倒立摆 + 反作用轮的结构里，机体受到的常值外力矩 `C` 无法由控制器"凭空"抵消，
只能通过机体倾斜（`kp·φ`）与轮速（`kw·ω`）两个自由度分担。当 `C` 大于
`kp·φ_max` 能提供的量时，剩下的只能由 `kw·ω` 兑换，于是轮速单调上升。
唯一的办法是**把 C 本身消掉**——拔掉调试线。

1. `User/Cfg/board_cfg.h`：`BAL_MAX_MS 15000u → 60000u`（S6b 判据需要连续 60 s；

2. `sim/s4_design.py`：`design_lqr(inertia, u0, sig_w=None)` 增加可选参数（默认仍取
   `SIGMA_OMEGA_RPM`），供扫描用；`KP/KD/KW` 手抄值与自校验不变。
3. 新增 `.tmp_env\s6_blind60.ps1`：预检 → `mode 2`/`start`/`bal on`/`bal run on` →
   长鸣 700 ms → 关闭串口 → 提示"松手并立刻拔 USB 线" → 等 `RunS+6` s →
   轮询等 COM13 回来（最多 120 s）→ 读 `bal run` → `bal run off`/`stop`。

### 数据

构建 `Code=79040 RO-data=3504 RW-data=612 ZI-data=14284`（`build_60s_a.log`），四门全绿。

首次盲跑（`Nov  5 2026 20;31;01 #1`）**没能武装**：

...
