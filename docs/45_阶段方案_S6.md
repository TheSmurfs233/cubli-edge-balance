## 1. 背景

S4 已把平衡律接进固件并跑通影子模式（`docs/00` #024）：真实 IMU 数据经 `mid_att` 得到 θ，
`alg_bal` 算出 `tau_cmd`，`corr(θ, τ) = 0.86`、静态点 `kp` 分力与手算差 0.02%。
但 `app_bal_update()` **全程不调用 `app_torque_set()`**——律在那里算，力矩从来不出去。

S6 要做的是把最后这一根线接上，并且**用一整套联锁把它包起来**：出错时力矩必须自己消失，
而不是等操作者反应。

三件事决定了 S6 不能一次做到"放手平衡"：

| 约束 | 现状 | 对 S6 的含义 |
|---|---|---|
| `18#T19` 物理反作用方向未验证 | 只能靠闭环首测判定 | 首测必须是"判定实验"，不是"展示实验"：允许它倒，不允许它带着满力矩倒 |
| `18#T22` 线缆外力 | 1 N × 5 cm = 50 mN·m > 全部力矩预算 34.7 mN·m | **带线不可能真平衡**；带线阶段只做方向判定，真平衡必须电池 + 无线 |
| `18#T20` 平衡点角度未知 | 现场 `att zero` 得到 46.92°，是手扶位置不是真平衡点 | 无积分时稳态会停在"轮速转起来顶住摩擦"的位置；S6 验收按"角度稳、轮速有界"而不是"轮速为零" |

## 4. 技术路线

### 4.1 编排层：`app_balance`（S6 新增）

放在 `User/App/`，**只做编排**，不做数学（数学在 `alg_bal`），不碰 HAL。

```
app_balance_update()            每轮主循环调用
  ├─ seq 未变 → 直接返回                     （零阶保持，200 Hz 新帧才动）
  ├─ 状态 == DISARMED → 直接返回
  ├─ 取 att_get() → 帧无效 → trip(STALE)
  ├─ 计算 alg_bal_step()  → tau_cmd
  ├─ 限幅：abs(tau) ≤ BAL_MAX_MNM，abs(dtau) ≤ BAL_SLEW_MNM_STEP
  ├─ 检查 TRIP 条件（表 4.3）
  ├─ trip  → app_torque_off(); app_stop(); state = TRIP
  └─ 正常  → app_torque_set(tau); 计时 + 累计统计
```

状态机（**硬优先级**：TRIP > DISARMED > ARMED > RUN，低优先级不得覆盖高优先级状态）：

| 状态 | 进入条件 | 允许的事情 |
|---|---|---|
| DISARMED | 上电、用户 `bal run off`、任何 STOP | 只有影子计算 |
| ARMED | `bal run on` 且 ARM 条件全满足 | 开始输出力矩 |
| RUN | 已输出力矩且未触发 TRIP | 持续输出 |
| TRIP | 任一 TRIP 条件 | 力矩已清零、PWM 已封，等待人工 `bal run off` |

### 4.2 为什么只在"新帧边沿"输出

`app_bal_update()` 现在每轮主循环都跑（~75 kHz），但姿态只有 200 Hz。
如果每轮都调 `app_torque_set()`，同一个 θ 会被施加 375 次，**PID 之外的隐式积分**就出现了：
`kd` 项在帧间保持不变，力矩会一直顶在一个非零值，等效于给系统加了纯摩擦。

正确做法与 L1 仿真一致：**5 ms 零阶保持**。实现上用 `att_get()->seq` 判新帧——
这与 `18#T16` 决定的"200 Hz 固定定时器取最新帧"等价，且不需要新增定时器。

### 4.3 ARM 与 TRIP 条件（全部进 `board_cfg.h`）

| 类别 | 条件 | 初值 | 依据 |
|---|---|---|---|
| ARM | 姿态有效 | `att_get()->valid == 1` | 无姿态不许出力 |
| ARM | `abs(theta) ≤` | `BAL_ARM_DEG 2.5°` | 0.7× 的捕获窗口是 4.50°，留 1.25° 余量（`L-13`：降额后窗口必须重新扫描，0.4× 时窗口是 0.00°） |
| ARM | `abs(theta_dot) ≤` | `BAL_ARM_DPS 30 °/s` | 快速倾倒时不接管 |
| ARM | `abs(omega) ≤` | `BAL_ARM_RPM 300 rpm` | 起手时轮子应基本静止 |
| ARM | 驱动就绪 | `app_torque_set()` 先决条件 | 返回 2/3/4 时拒绝 ARM 并打印原因 |
| TRIP | `abs(theta) >` | `BAL_TRIP_DEG 12°` | 2.73° 已饱和，12° 说明已经倒了 |
| TRIP | `abs(theta_dot) >` | `BAL_TRIP_DPS 200 °/s` | 高速倾倒 |
| TRIP | `abs(omega) >` | `BAL_TRIP_RPM 1700 rpm` | `L-12`：1700 rpm 以上剩余力矩 < 7 mN·m；1200 太紧（零点差 0.5° 就需 ~990 rpm 常值轮速，会在环路还没展开时就跳闸） |
| TRIP | 帧龄 | `> BAL_TRIP_STALE_MS 50 ms` | 200 Hz 下丢 10 帧 |
| TRIP | 故障 | `app_status()->fault != 0` | 过流/过压等直接停 |
| TRIP | 时长 | `> BAL_MAX_MS`（S6a 3000 / S6b 120000） | 首测自动停 |

### 4.4 增益与首测降额

| 阶段 | kp [N·m/rad] | kd [N·m/(rad/s)] | kw [N·m/(rad/s)] | 说明 |
|---|---|---|---|---|
| L1 标称 | 0.728 | 0.0970 | 4.0e-05 | 仿真收敛 ±4.5° |
| S6a 首测 | **0.510** | 0.0679 | 2.8e-05 | **0.7×** 降额（原方案 0.4×，扫出捕获窗口 0.00° 后改）：符号错时发散慢，且仍有 4.50° 窗口 |
| S6b | 0.728 | 0.0970 | 4.0e-05 | 标称，进 S6b 前先用 S6a 确认符号 |

降额通过 `BAL_SCALE` 一个宏实现（0.7 / 1.0），不改 `BAL_KP_*` 原值，避免"调参数把标称值弄丢"。

### 4.5 力矩限幅与速率限制

- 幅值：`abs(tau) ≤ BAL_MAX_MNM (28.0)`，低于 S4 的 34（先于 `app_torque_set` 生效），也低于纹波把相电流峰值顶过 `FOC_I_TRIP_A` 的水平（§4.11）。
- 速率：`abs(dtau) ≤ BAL_SLEW_MNM_STEP (10.0)` 每 5 ms ⇒ **2000 mN·m/s**，0→28 约 14 ms。
  理由：电流环本身很快，真正的风险是**指令跳变**激励机械共振与结构件松动；
  16.5 ms 相对 1.2 Hz 的闭环带宽仍是"足够快"。
- 死区：沿用 `ALG_BAL_TAU_MIN_MNM (1.0)`，避免在零附近抖。

### 4.6 与 `app_torque_set()` 的关系

- 编排层**只**通过 `app_torque_set()` 出力，不直接写 `app_foc_set()`；限幅仍然只有一处。
- `app_torque_set()` 返回 5（超上限）/6（速度环占用）时视为 TRIP，并打印错误码。
- TRIP 的停机顺序固定：`app_torque_off()` → `app_stop()`。
  先清指令再停 PWM，避免"停 PWM 那一拍电流环还拿着旧 iq"。

### 4.7 可观测（这是 S6 能不能调出来的关键）

| 命令 | 内容 |
|---|---|
| `bal run on` / `bal run off` | 显式 ARM / DISARM，打印被拒原因 |
| `bal` | 增加 `arm`/`run` 状态、`trip` 原因码、`tau` 与三项分力、饱和/限幅标志 |
| `bal log <s>` | CSV 增列 `state,trip,tau,phi,rate,rpm`（20 ms 一行，50 Hz） |
| `bal stat` | 本次运行统计：最长连续保持、`abs(theta)` 均方根、饱和占比、最大 `abs(omega)` |

### 4.8 被否掉的备选

| 方案 | 否决理由 |
|---|---|
| 直接在 `app_bal_update()` 末尾调 `app_torque_set()` | 无联锁、无速率限制、无新帧边沿（隐式积分），且出事后无法解释 |
| 用 1 kHz 速度环外挂力矩 | 速度环有积分，会把恒力矩吃掉，且 1 kHz 与 200 Hz 两个环带宽接近会耦合 |
| 用一个独立定时器驱动 200 Hz 闭环 | 与 `18#T16` 结论重复；主循环 + seq 边沿已等价，少一处时基就少一个 bug |
| 首测直接用标称增益 | 符号错时会在 100 ms 内把轮子推到 1200 rpm，来不及断电 |

### 4.9 实现要点（代码与方案的四处偏离，均已验证）

| # | 方案里写的 | 实际采用的 | 为什么 |
|---|---|---|---|
| 1 | "新帧边沿 = `att_get()->seq` 变化" | **IMU 帧计数 `imu_ctx()->stat.frames`** | `mid_att` 每次 `att_update()` 都会自增自己的 `seq`，75 kHz 主循环会让它看起来"每拍都有新帧"，边沿判据形同虚设。L2 用"同一帧重复提交时 `frames` 不增"锁死这条 |
| 2 | "帧龄 > 50 ms 触发 TRIP" | **实时读 `imu_frame_age_ms()`**，不用 `att_state.age_ms` | `age_ms` 只在 `att_update()` 里刷新；IMU 断流时 `att` 不再更新，陈旧值永远小于阈值，联锁会瞎掉 |
| 3 | "编译期断言保证 `BAL_*` 阈值顺序" | **`bal_cfg_load()` 启动告警 + L2 断言** | C 的整数常量表达式不允许浮点操作数，负数组技巧会退化成 VLA（gcc 报 `variably modified at file scope`，ARMCC 同理）。改成启动时 `WARN bal: BAL_* threshold order looks wrong` |
| 4 | 首测降额 0.4× | **0.7×，ARM 窗口 2.5°** | 实测 0.4× 的捕获窗口是 **0.00°**：那套参数 ARM 3° 等于"武装一个已经输了的环路"。0.7× 捕获 4.50°，2.5° 留 1.25° 余量（`sim/s6_scale_scan.py`） |

另外三条实现细节：

- **ARM 会自动打开影子律**（`app_bal_set(1)`），否则编排层拿不到 `tau`。`bal run` 的打印把"律的输出"和"实际下发"分成两个数。
- **TRIP 是锁存的**：TRIP 状态下 `app_balance_arm(1)` 直接拒绝，必须 `bal run off` 清除后再 `mode 2` + `start`。这是 S6a 之前唯一的人工确认环节，不为方便而放开。
- **驱动就绪检查不能借 `app_torque_set(0)`**：零力矩会短路成 `app_torque_off()` 并恒返回 0，测不出任何东西。改为直接看 `app_status()->state == APP_ST_RUN`、`mode == CTRL_FOC`、`s_spd.on == 0`。

### 4.10 轮速单方向累积（`18#T20`）：四条路线只留下摩擦前馈

S6a 第一跑暴露的现象：`phi` 稳定在 0.3°，轮速却一路涨到 754 rpm 并继续爬。这不是失稳，是结构性的。

稳态时力矩方程是 `kp*theta + kw*omega = tau_f + mgh*sin(theta0)`，解出

```
omega_ss = (tau_f - kp*theta0) / kw
```

`kw = 4.0e-5 N.m/(rad/s)` 很小，所以任何常值力矩残差都要用很大的轮速去"兑换"：零点误差 0.2° 就要 1200 rpm，0.5° 直接倒。**电机必须自己付掉库仑摩擦和零点力矩，否则轮子必然单向累积。**

四条路线都试过（`sim/s4_design.py` 的 `simulate()` 已支持全部参数，20 s~120 s、含静摩擦锁死模型）：

| 路线 | 零点误差 0.2° 的结果 | 判定 |
|---|---|---|
| A 轮速积分（4 状态，`ki=1e-5`） | 倒（phi 213°） | ❌ 与静摩擦对抗，反复过冲 |
| B 角度零点自适应（`trim' = k*omega`，clamp ±0.3~1°） | 倒 | ❌ trim 被推到 clamp，`kp*trim` 成了大于 `tau_f` 的常值推力 |
| C 力矩偏置（`bias' = -k*omega`，clamp ±3~4 mN.m） | 倒 | ❌ 方向反了会加剧饱和；方向对了也压不住 `kw*omega` |
| D **摩擦前馈**（`u += sgn(omega)*tau_f`，迟滞带 0.5 rad/s） | **-710 rpm，不倒** | ✅ 采用 |

采用 D 后：零点误差 0° → **-104 rpm**（几乎不转），0.2° → -710 rpm，0.5° → -1620 rpm（会跳闸但不倒）。机理是把常值项直接补上，`kw*omega` 只需兑换剩下的零点误差。脚本 `sim/s6_t20.py`，曲线 `sim/figs/s6_1_t20.png`。

实现要点：
- ff 用**轮子**的符号而不是倾角符号（它补偿的是摩擦，摩擦与轮速反向），带 30 rpm 迟滞防止零速附近抖动；
- ff **不乘** `cfg.sign`：它是物理力矩，不是控制决策，装反了 IMU 不该把它翻过来（L1 16d 锁死这条）；
- 残下的零点误差交给 `bal trim <deg>`：`phi_law = theta - trim`，只改 RAM，重启回 `BAL_TRIM_DEG`，夹在 ±`BAL_TRIM_MAX_DEG`。

### 4.11 力矩上限被相电流纹波吃掉（`BAL_MAX_MNM` 33 → 28 mN·m）

**现象**（2026-11-04 上板，固件 `22;56;21`）：闭环跑到 3.2 s 被 `fault` 打断，`counts oc 1`，
当时 `peaks phi 7.59 deg / wheel 116 rpm / torque 33.00 mN.m / saturated 91`。轮速只有 116 rpm，
说明**前馈把单向累积压住了**（上一版无前馈是 754→1200+ rpm），它不是失效，而是被过流保护误杀。

**根因（解析）**：过流判据比的是**瞬时相电流峰值**，而相电流 = 指令 iq + 开关纹波。纹波
`ΔI_pp = Vbus·D(1−D)/(fsw·L)`，最坏 `D=0.5`，`L=0.5 mH`、`fsw=20 kHz`：

| 母线 | 纹波 p-p | 纹波峰 |
|---|---|---|
| 12.0 V（台架） | 0.300 A | 0.150 A |
| 14.03 V（4S 实测） | 0.351 A | 0.175 A |
| 16.8 V（4S 满电） | 0.420 A | 0.210 A |

于是在 33 mN·m（iq 1.141 A）时峰值电流 = 1.141 + 0.175 = **1.317 A > `FOC_I_TRIP_A` 1.28 A**。
12 V 时就已经是 1.291 A > 1.28 A —— **换电池只是把本来就在边缘的余量彻底顶穿**，
并不是 4S 引入了新问题，而是暴露了旧余量本就不足。

**修法**：`BAL_MAX_MNM 33.0f → 28.0f`（iq 0.969 A）。复算（`sim/s6_ripple.py`）：

| 上限 | iq | 12 V 峰 | 14.03 V 峰 | 16.8 V 峰 |
|---|---|---|---|---|
| 33 mN·m（旧） | 1.141 A | 1.291 TRIP | 1.317 TRIP | 1.351 TRIP |
| 30 mN·m | 1.038 A | 1.188 OK | 1.213 OK | 1.248 OK |
| **28 mN·m（新）** | 0.969 A | 1.119 OK | **1.144 OK** | 1.179 OK |

28 mN·m 在满电 16.8 V 下仍有 0.10 A 余量，且 28 > 捕获窗口需要的力矩（`±2.5°` 时静态需求
`mgh·sin2.5° = 14.3 mN·m`，0.7× 增益的指令更小）。

**为什么不改过流阈值**：`FOC_I_TRIP_A` 1.28 A 已经是采样链路（±1.32 A 饱和）的合理上界，
再往上调就进了 ADC 饱和区，属于**放宽保护**；正确做法是让指令给出足够的纹波余量。

**遗留**：这是"用限幅掩盖判据缺陷"。更彻底的做法是把跳闸判据从瞬时峰值改成滤波后的电流
或 iq/id 矢量幅值（另加一条更快的硬阈值兜底），属保护逻辑重构，放进 S7 鲁棒性阶段。

**后续（同一根因的第二处）**：28 mN·m 版首轮仍然跳 `oc 1`，这次不是纹波而是**指令阶跃**。
`BAL_SLEW_MNM_STEP 10 mN·m/帧` 等于每 5 ms 把 iq 抬高 0.35 A，20 kHz 电流环对这种阶跃的
超调量约等于阶跃本身 ⇒ 稳态 0.97 A 上叠 0.35 A ≈ **1.31 A > 1.28 A**。修法是把速率降到
`BAL_SLEW_MNM_STEP 3.0f`（每帧 0.104 A，0→28 约 50 ms，相对 1.2 Hz 的闭环仍然够快）。
记忆点：**限幅要看"峰值 = 稳态 + 纹波 + 阶跃超调"，三者都要预算**。

### 4.12 残余轮速来自常值外力，用慢速零点自适应吸收（`18#T20` 第二级）

**现象**（2026-11-05 上板，固件 `23;09;32`，`slew 3.00`）：闭环**连续撑住 6132 ms、1842 帧**，
`peaks phi 1.98 deg / rate 0.01 deg/s / wheel 1696.78 rpm`，`peak torque 22.43`、`saturated 0`、
`counts oc 0`，最后止于 `trip wheel`（1700 rpm）。姿态、符号、降额、前馈、slew 全部对上，
**唯一没解决的是轮速单调上升** —— 摩擦前馈只能付掉库仑摩擦，付不掉外部常值力矩。

**定性**：6.1 s 内轮速涨到 1697 rpm，按 `J_w = 5.12e-5` 反推平均只需要 **~1.5 mN·m** 常值力矩，
量级与"USB 线挂在中点、1 N 量级横向力 × 3~5 cm 力臂"一致（`18#T22`）。这不是控制律的缺陷，
而是**机体上存在未知常值外力矩**，只能由 `kw·omega` 兑换 —— 于是轮速必须一直转。

**为什么不是积分**：4 状态（对 `omega` 积分）在 L1 里就是极限环制造机（§4.7）。真正可行的形态是
**慢速零点自适应（trim）**：把"需要多少常值力矩"，换成"零点该偏多少角度"，即
`mgh·sin(trim) = -(ext + tau_f)`，让重力去承担常值力矩，轮速因此不必再累积。

**符号推导（最容易写错的地方）**：`tau = kp·(phi - trim)`，若外部常值力矩为正（推着机体往前倒），
就需要机体**向前倾一点**来借重力，也就是 **trim 必须往负方向走** ⇒ 更新式是

```
u_lp  = 一阶低通(u_law, tau = 0.5 s)          // 用"指令"而不是"轮速"做驱动
trim -= k · u_lp · dt                          // 正指令 → trim 变负
```

仿真里第一次写成 `trim += k·u_lp·dt`，闭环立刻发散 —— 这正是早先"角度零点自适应"失败的真正原因
（不是方法不行，是符号反了）。

**参数扫描**（`sim/t20_trim.py`，`ext = 1.0~3.0 mN·m`、`u_max = 28`、ff 2.05 mN·m、轮速死区 3.14 rad/s）：

| `k` [deg/s per mN·m] | 结果 | `max phi` | `max rpm` | 末端轮速（`ext=1.5`） |
|---|---|---|---|---|
| 0（不补偿） | 不倒 | 0.62 deg | 968 | 956 rpm |
| **0.1（选定）** | 不倒 | 1.04 deg | 965 | **289 rpm** |
| 0.3 | 倒 | — | — | — |
| 0.5 | 倒 | — | — | — |

选定 **`k = 0.1`、`tau = 0.5 s`、`gate = 3 deg`、`clamp = 2 deg`**：比不补偿把末端轮速降了约 70%，
同时对 `0.4~3.0 mN·m` 的外力都不失稳。`k` 再大就开始和 1.2 Hz 的姿态环抢频带。

**实现要点**：
- `alg_bal_adapt(float dt_s)` 用 `s_law_mnm`（**乘 `sign` 与叠 ff 之前**的原始律输出）驱动低通；
  用"指令"而不是"轮速"是因为指令里已经含了姿态信息，带宽足够低（0.5 s）就不会与姿态环打架。
- `abs(phi) > trim_gate_deg` 时**直接返回**：大角度是倒伏过程，不是"常值外力"，此时改零点只会添乱。
- `trim` 钳在 `±clamp`（2°）：再大就说明不是线缆而是机械问题，应该停机而不是继续补偿。
- `alg_bal_reset()` 把 trim 复位到编译期 `BAL_TRIM_DEG`；`bal trim <deg>` 手动覆盖（只改 RAM）。
- 单位仍是"度"进"弧度"算：`s_trim_rad -= (k * u_lp * DEG2RAD) * dt`，`k` 的单位因此是
  `deg/s per mN·m`，不要和 `N·m/rad` 的增益混写。

### 4.13 增益权重重定：轮速已经不是瓶颈（2026-11-05）

2026-11-05 的连续三次上板循环得到一个不能忽略的事实：环路本身是收敛的，
倾角一直被压在 ±1.6°，但轮速在 2.5~3.2 s 内从 0 冲到 1700 rpm 触发跳闸。

定量（`J = 5.12e-5`）：

| 次 | 假定零点 | 窗口 | 末端轮速 | α | 多余力矩 | 等效零点误差 |
|---|---|---|---|---|---|---|
| A | 46.0° | 6132 ms | 1697 rpm | 29.0 rad/s² | 1.48 mN·m | 0.26° |
| B | 45.4° | 3218 ms | 1699 rpm | 55.3 rad/s² | 2.83 mN·m | 0.49° |
| C | 45.4° + trim 1.2 | 3023 ms | 1695 rpm | 58.7 rad/s² | 3.00 mN·m | 0.52° |

A/B/C 三次的扫分不单调（按线性拟合 C 应该比 B 好），说明**带线时常值外扰的波动就有
±1.5 mN·m，与要标定的零点误差同量级**（即 `18#T22`）——带线状态下无法标定零点。

于是换了一个角度：不再追求零点精度，而是**把“用轮速买常值力矩”的兑换率降下来**。
稳态关系是

```
ω_ss = mgh·sin(θ_0) / kw        # θ_0 = 零点误差
```

旧 kw 是 `4.0e-5`，0.5° 误差要买 980 rpm；新 kw 是 `3.82e-4`，同一个误差只买 103 rpm。
代价也说清楚：指令饱和角从 `τ_max/kp = 2.73°` 缩到 `1.51°`，但**捕获窗口不变**（模拟：4.5° 收得住、5° 收不住），
因为大角度靠的是轮动量。

改动清单：`BAL_KP_NM_RAD 0.728 -> 1.31383`、`BAL_KD_NM_RPS 0.0970 -> 0.175517`、
`BAL_KW_NM_RPS 4.0e-5 -> 3.819719e-4`；`sim/s4_design.py` 的 `design_lqr()` 把轮速权重从
`1/50^2`（单位未定义，实际 50 rad/s）改为 `σ_ω = 50 rpm`并自检；L1 的 15a~15c 金标值与
L2 的 `22.93 mN·m/deg` 同步更新。

模拟结果（`sim/s4_design.py`）：

| 情形 | 旧增益 | 新增益 |
|---|---|---|
| 1.5 mN·m 常值外扰 + 0.5° 零点误差，120 s | 末端 1523 rpm | **304 rpm** |
| 释放 3° | RECOVER 0.40 s | RECOVER 0.81 s |
| 释放 4.5° | RECOVER | RECOVER |
| 释放 5° | FALL | FALL |
| 延时 20 ms | RECOVER | RECOVER（峰值轮速 792 -> 1106 rpm） |
| 噪声 0.10° | RECOVER | RECOVER |

下一步：这一组增益尚未上板，需用户烧录后复测；若轮速不再单向堆到轮速跳闸，
`18#T20` 可降级为“常值外扲已由增益吸收，剩余零点交给 `bal trim`”。

### 4.14 “被持住”检测：一只自由的立方体拒绝不了力矩（2026-11-05）

2026-11-05 晚连续三轮闭环都在 0.5~1.5 s 内 `trip wheel`，但轮轴小得离谱：**0.16 s 的满力矩就能给它加 836 rpm**。

一轮具体数据（窗口 548 ms、165 帧、饱和 29 帧）：

| 量 | 值 | 推理 |
|---|---|---|
| 峰值 phi | 1.14° | `kp*phi = 22.9 x 1.14 = 26 mN·m`，已经压在上限上 |
| 峰值 rate | **0.13 °/s** | 机体几乎不动 |
| 峰值轮速 | 1692.7 rpm | 轮子把全部力矩吃掉了 |

矛盾在于：同一个 26 mN·m 反作用也作用在机体上，`alpha = 28e-3/3.31e-3 = 8.5 rad/s²`，
0.35 s 后机体应该转到 **171 °/s**；实测只有 0.13 °/s，差了 1300 倍。
**结论：那一刻立方体被人手或 USB 线持住了。** 这不是调参错，是实验条件错：
平衡环推不动一个被固定的机体，只能把轮子越转越快。

修法（只加严不放宽）：`User/Cfg/board_cfg.h` 新增

```
BAL_HELD_MNM   12.0f   /* 律输出超过它就算“在推” */
BAL_HELD_DPS    5.0f   /* 机体角速度低于它就算“不动” */
BAL_HELD_MS     150u   /* 200 Hz 下 30 帧 */
```

`User/App/app_main.c` 在 `app_bal_update()` 之后、限幅之前检查：律输出
`>= BAL_HELD_MNM` 且 `abs(rate) <= BAL_HELD_DPS` 时计数，达到 `BAL_HELD_MS` 就
`bal_trip(BAL_TRIP_HELD)`（停机顺序不变：`app_torque_off()` → `app_stop()`）。
状态名为 `held`，与 `tilt`/`wheel` 区分，可从 `bal run` 直接看出这一轮为何停。

为何阈值取 12 mN·m / 5 °/s：正常平衡时律输出只有几 mN·m（常量外扰 ~2 mN·m）；
而真正的快捕获时机体角速度很大（实测 122 °/s），会被 rate 条件排除。
150 ms 内跳闸，轮子只会被带到 ~420 rpm，远离 1700 rpm 窗口。

验证：Keil `-r` 0E0W `Code=78868 RO=3504 RW=608 ZI=14280`；L2 新增一段（恒定 6° + 零角速
喂 40 帧 → 200 ms 内 `trip held`），总数 699；四门 11 / 15+13+29 / 699 / PASS。

### 4.15 松手即接管：把“武装”和“出力”拆成两步（2026-11-05）

被持住检测（4.14）能把失败**说出来**，但不能让它**不发生**。实测代价很硬：

| 轮次 | arm 后多久松手 | 结果 |
|---|---|---|
| 提示音起跑第 1 次 | 没松（arm 前就倒了） | `ERR tilt 44.36 deg`，电机未动 |
| 提示音起跑第 2 次 | 约 265 ms | `trip held`，轮子已被带到 **403 rpm** |

人的反应时延 150~250 ms，而轮子 0.16 s 就能吃到 836 rpm。**只要“武装”和“出力”是同一
瞬间，这个竞赛就必输**，而且输掉的部分直接扣在轮速预算里。

修法：`bal run on` 只**武装**，不出力。`app_balance_update()` 在拿到新姿态帧后先看机体是否
已经开始动：

```
BAL_ENGAGE_DPS   2.0f   /* 机体角速度超过它 = 操作者松手了（主判据） */
BAL_ENGAGE_DEG   3.0f   /* 兜底，必须大于 BAL_ARM_DEG */
```

未越过阈值时：状态停在 `armed`、`applied` 恒为 0、`frames` 不增，**一个字节的力矩都不发给
电机**，所以扶着多久都不会卷轮子。越过后：清 `s_tau_cmd = 0`、把 `s_run_t0` 重置为此刻
（等待时间不计入 `BAL_MAX_MS` 跑道），从零开始斜坡出力。

判据为什么是 2 °/s：松手后 0.5° 的偏置按 `Omega = 10 rad/s` 增长，`2 °/s` 出现在松手后
约 **45 ms**，此时倾角约 0.5°，离 4.5° 捕获窗口还很远；而扶在手里时角速度是 0.1~0.2 °/s
（实测静止零偏 0.14 °/s），不会误触发。

`bal run` 的输出多一个后缀：`state = armed, waiting for release`，一眼能看出“已武装、
还等着你松手”。被持住检测在等待态**不参与**（不然扶着就跳闸，松手的机会都没有）。

验证：Keil `-r` 0E0W `Code=79012 RO-data=3504 RW-data=608 ZI-data=14280`；
L2 新增一段（武装后喂同角度帧 → `engaged == 0`、`frames == 0`、`applied == 0`、
屏幕含 `waiting for release`），总数 **704**；四门 11 / 15+13+29 / 704 / PASS。

#### 4.15.1 首版阈值把功能废掉了（2026-11-05 实测）

第一版取 `BAL_ENGAGE_DEG 0.6°`，**小于 ARM 窗口 2.5°**。于是操作者扶着立方体站在
1.55° 时，武装后的第一帧就满足"倾角 >= 0.6°"，**立即接管**——等于什么都没改。

实测那一轮：

| 量 | 值 | 说明 |
|---|---|---|
| 预检 phi | -1.55° | 手扶位置，落在 ARM 窗口内 |
| engaged | 0.25 s | 不是"松手后 0.25 s"，而是立刻 |
| 窗口 | 578 ms、饱和 92/175 帧 | 又变成和手较劲 |
| 峰值轮速 | 1693.7 rpm | 再次撞上 `wheel` TRIP |
| 结束时刻 rate | 425 °/s | 机体已被推着倒下 |

修法：`BAL_ENGAGE_DEG` 抬到 **3.0°**（严格大于 `BAL_ARM_DEG 2.5°`），并把它降级为
"兜底"——主判据是角速度 2 °/s。判据成立的前提是**武装时手扶角度不会触发它**，
这条现在写进宏注释。

L2 相应改成"喂一帧带 30 °/s 的帧才算松手"（新增 `att_feed_rate()`，把速率写进
`ATT_AXIS` 对应的角速度字段，`att_feed()` 退化为 `rate = 0` 的包装）。

#### 4.15.2 2 °/s 也会被手的抖动触发（同日第二次）

把兜底抬到 3° 后再跑，`engaged` 仍在 0.25 s 出现——这次是**角速度判据**被手抖动了。
那一轮：`trip held`、窗口 442 ms、`peaks phi 1.18° / rate 50.74 °/s / wheel 547.7 rpm`、
`applied 0`、`law -28.00`。也就是说：手把立方体晃到 2 °/s，环路接管，开始和手较劲，
400 ms 后被"被持住"检测喊停。

结论：**2 °/s 落在人手的噪声里**（静止搁在桌面上的零偏是 0.14 °/s，但一只手扶着时
抖动远大于它）。判据要选"手做不出来、自由倾倒一定做得到"的量：

```
BAL_ENGAGE_DPS     8.0f   /* 松手后 0.5° 偏置约 0.13 s 达到，倾角约 1.7° */
BAL_ENGAGE_FRAMES  3u     /* 连续 3 帧（15 ms），抖动不会持续同向 */
```

并且**删掉倾角兜底**：手可以把它扶在任意角度，任何"角度够大就算在倒"的判据都会重新
短路主判据（这是 4.15.1 的同一个坑）。角度约束交给 ARM 窗口（2.5°）去管。

丢掉的时间：从松手到 8 °/s 约 0.13 s，倾角约 1.7°，相对 4.5° 捕获窗口仍有余量。

验证：Keil `-r` 0E0W `Code=79012 RO-data=3504 RW-data=612 ZI-data=14284`；
L2 改为"连喂 3 帧 30 °/s 才接管"（1 帧不接管、2 帧不接管、第 3 帧接管并开始出力），
总数 **709**；四门 11 / 15+13+29 / 709 / PASS。

#### 4.15.3 接管成功，却被“被持住”检测误杀（同日第三次）

8 °/s 的松手判据生效了：`engaged` 出现在 **2.12 s**（此前都是 0.25 s），说明它真的等了
两秒才等到松手。随后：

| 量 | 值 |
|---|---|
| 窗口 | 1066 ms、320 帧、饱和 0 |
| 峰值 phi | **0.46°**（整整一秒摁在平衡点附近） |
| 轮速 | 543 rpm |
| 结束 | `trip held`，随后立方体倒下 |

**判据分析**：`held` 的三个条件同时成立——`tau` 28 mN·m（其中 `kw*omega` 在 543 rpm
贡献 15 mN·m）、`rate` ≤ 5 °/s、持续 150 ms。但一个**调好的平衡环本来就是这样**：
力矩大、机体几乎不动正是它的目标。判据把"平衡成功"读成了"被攥住"。

**修法**：加偏角前置条件 `BAL_HELD_DEG 1.0f`——只有明显偏离平衡（`abs(phi) >= 1.0°`）
时，才允许把大力矩解释成"跟手较劲"。此前的两次真·被持住 phi 是 1.14° / 1.18°，
仍会被抓到；而 0.46° 的这轮不会再中招。

验证：Keil `-r` 0E0W `Code=79028 RO-data=3504 RW-data=612 ZI-data=14284`；
L2 **710**（新增"小偏角 + 大力矩不算被持住"一条）；四门 11 / 15+13+29 / 710 / PASS。

### 4.16 S6b 执行手册（拔线盲跑，60 s）

**为什么必须拔线**：调试线在机体上是一个常值外力矩 `C ≈ 15 mN·m`（由轮速累积斜率反推，
见 4.13）。倒立摆 + 反作用轮的结构里 `C` 只能被 `kp·φ` 与 `kw·ω` 两个自由度分担，
`C` 一旦超过 `kp·φ` 的量，剩下的全由 `kw·ω` 兑换，于是轮速单调上升。
仿真给出 `ext = 15 mN·m` 时稳态轮速 1480 rpm（实测 1327 rpm 同量级），
**提高 kw 只有 30% 收益、捕获窗一点不变**。唯一办法是把 `C` 本身消掉。

**前提检查（任一不满足就不要开跑）**

| 项 | 命令 | 通过条件 | 失败含义 |
|---|---|---|---|
| 母线电压 | `vbus` | ≥ 13.5 V | 低于 `VBUS_UV_V 12.0 V` 时 `start` 后 50 ms 内欠压停机，`bal run` 会报 `send 'mode 2' and 'start' first`（电机完全不动作） |
| 编码器 | `enc` | `raw` 非 0、`mg 0`、`crc ok`、转动时 `raw` 跟随 | 全零帧的 CRC6 恰好也是 0，会"假通过"（`90#L-16`） |
| 姿态 | `att` | `bs(roll) ≤ 3°`、`link = OK`、`age ≤ 10 ms` | 立方体没立在棱上（立棱读数应接近 0，平放约 −46°） |
| 固件 | `ver` | `build` 时间与刚烧录的一致 | 烧错版本 |

**执行**

1. 立方体立在棱上、手扶着（扶住即可，不需要精确到 0.1°）；
2. 跑 `.tmp_env\s6_blind60.ps1 -PhiTol 3.0 -RunS 60`；
3. 脚本打印 `>>> RELEASE, THEN UNPLUG THE USB CABLE NOW <<<` 并长鸣 700 ms：
   **先松手，立刻拔掉 USB 线**（线一拔，`C` 归零）；
4. 板子靠电池继续跑 60 s，脚本 66 s 后开始轮询等 COM13 回来；
5. 插回 USB 线，脚本自动读 `bal run` 并打印窗口数据。

**判据**

- 通过：`window ≥ 60000 ms`、`trip none`、`peaks phi` 在平衡点附近小幅摆动、
  `peaks wheel` 远低于 1700 rpm（预期从带线的 1300+ 降到几十到一两百）；
- 失败分支：
  - `trip wheel` 且轮速很快到 1700 → 说明还有外力（线没拔干净 / 手还扶着）；
  - `trip held` → 被持住，看 `BAL_HELD_*`；
  - `trip tilt/rate` → 松手位置超出捕获窗（3°），重新摆；
  - `state = disarmed` → 武装就被拒，看打印的原因（多半是电压或姿态）。

**仪器事实**：拔线期间串口不存在，`wave`/`bal log` 这类实时抓取都不可用；
`bal run` 的统计在 RAM 里，插回线后读得到。板子断电会清零。

### 4.17 按钮长按启动（2026-11-06）

**问题**：`bal run on` 之后要靠"松手"触发接管（`BAL_ENGAGE_DPS 8 °/s` × 3 帧，见 §4.15）。
人的手扶住立方体时，抖动本身就常超过 8 °/s；一旦误触发，第一条指令就是
`kd × 8 °/s ≈ 24 mN·m`，0.47 s 把轮子推到 1699 rpm（`docs/00` #032）。
反过来，如果真等它开始倒再接管，`kd` 项同样会给出一记 −24 mN·m 的冲击。
"等松手才出力"与"接管不能有力矩冲击"在结构上矛盾。

**做法（2026-11-06 第二版，按用户要求改成"按一下就松手"）**：

- **短按 + 松开**：按下即为"预备"（LED 翻转；若已武装则先解除武装），松开后
  `BAL_KEY_START_DELAY_MS = 3000 ms` 到点再由固件完成 ①`att_zero()` 取当前姿态为零点
  ②`app_set_mode(CTRL_FOC)` + `app_start()` 把驱动自己拉起来 ③武装 ④**立即接管**。
  这 3 s 留给操作者把立方体扶正、把手拿开。
- **长按 `BAL_KEY_HOLD_MS = 3000 ms`**：跳过等待，立即完成上面四步（台架用）。
- 接管后的前 `BAL_ENGAGE_RAMP_MS = 800 ms`，力矩上限从 `BAL_SLEW_MNM_STEP` 线性长到
  `BAL_MAX_MNM`——松手瞬间姿态有几百毫弧度误差也只出几 mN·m。
- 已武装时按一下 = 解除武装（不依赖串口的安全阀）。

> **为什么按钮必须自己拉起驱动**：第一版只调 `app_balance_arm()`，而 `APP_ST_RUN` 是
> `start` 命令才置的，于是长按只能打印 `refused (rc 5)`（驱动未就绪），现场看到的就是
> "按了没反应"。现在 `app_balance_start_now()` 内部先 `app_set_mode(CTRL_FOC)` 再 `app_start()`，
> 两者只是打开桥臂、停在 50% 零矢量并跑电流零漂校准，**不出力矩**，真正的力矩仍由平衡律决定。

**为什么先设零点**：编译常量 `ATT_OFFSET_DEG` 与真实平衡点可差 0.9°，
而 `sim/s6_disturb.py` 显示 2° 零点偏差就会把稳态轮速推到 1239 rpm。
按钮启动时由操作者指定零点，比猜常量可靠，也省掉"每次上板都要 `att zero`"的手工步骤。

**验收（L2 `[button start]`，4 段 13 条）**：从 `IDLE` 一次调用即进入 `RUN/FOC` 并接管；姿态帧过期时返回 1；
成功时 `engaged` 立即为 1、`theta ≈ 0`（被扶姿态成为零点）；
2° 倾角下首条指令 `≤ BAL_SLEW_MNM_STEP`；推进 820 ms 后力矩可继续增长。

### 4.18 轮速驱动的零点游走：把"轮速就是零点误差"变成执行机构（2026-11-06）

**现象**：连续三次满窗（13.8/14.3/14.0 s）之后，一次 60 s 长跑里 `phi` 稳定在 **-2.32 deg**、
`wheel` 稳定在 **1340 rpm**、`saturated = 0` —— 不抖、不饱和、不倒，只是轮子一直在转。

**机理**：机体被重力钉在真实平衡点（`mgh*sin(phi_true) - tau + fr = 0`，飞轮 `tau - fr = 0`，相减得
`phi_true = 0`），于是控制律 `tau = kp*(phi - trim) + kd*phi' + kw*omega + ff` 的稳态解是

```
omega_ss = (kp/kw) * (trim - phi_ss)
```

`kp/kw = 22.9/0.040 = 573 rpm/deg`，2.32 deg 应给 1329 rpm，实测 1340（差 0.9%）。
**轮速因此就是零点误差的读数**：要它归零，只能让 `trim` 跟着 `phi_ss` 走。

**为什么不能"直接刹轮"**：刹轮必须给负力矩，反作用把机体推离平衡点，还得靠重力拉回来 ——
轮子的角动量只能借"机体先歪一下"再还给重力。唯一可用的旋钮是参考角。

**方案**：`trim -= BAL_TRIM_W_K * omega_rpm * dt`（deg per rpm per second），
门限 `abs(phi) < BAL_TRIM_GATE_DEG 4 deg`、钳位 `+-BAL_TRIM_MAX_DEG 3 deg`、仅 `RUN && engaged` 时游走。
自校正：轮速正 → trim 往负 → 误差变小 → 轮速变小 → 游走自动停下。

**仿真**（`sim/s6_auto_trim2.py`，零误差 2.3 deg、70 s；旧 `s4_design.simulate` 的 trim 分支没有钳位，
第一次跑 trim 冲到 133 deg，数字不可信，所以另写了两状态积分器）：

| `trim_w_k` (deg/(rpm*s)) | 40 s 时轮速 | 机体最大偏移 | 到 60 rpm |
|---|---|---|---|
| 0（上一版） | 1340（不降） | — | 永不 |
| 1e-4 | 17 rpm | -2.52 deg | 36 s |
| **3e-4（采用）** | 约 0 | -2.62 deg | 17 s |
| 1e-3 | 0 | -3.11 deg | 5 s |

**同时改的另外三项**：

1. **一次性零点学习**：接管 1 s（`BAL_LEARN_MS`）后把观测到的 `theta` 直接设为 trim（0.15 deg <
   `abs(theta)` < 4 deg 才做），一次抹掉"编译零点 45.4 vs 实测 46.3"这类错误；之后的慢漂交给上面的轮速游走。
2. **取消 60 s 时间窗口**：`BAL_MAX_MS 60000 -> 0`（0 = 不限时）。窗口本是为"手扶装样子"兜底，
   而现在有 engage-on-release 与 held 两条判据；60 s 恰恰是那几次健康运行唯一的结束原因。
3. **ARM 窗口 2.5 -> 2.0 deg**（0.7x 捕获 3.75 deg，余量 1.75 deg），并新增 `bal auto on|off` 运行时开关
   （手动 `bal trim <deg>` 会自动关掉游走），`bal` 屏幕多一行 `auto`，`bal run` 的 `max` 行在 0 时印 `no limit`。

**待上板验证**：轮速应在一个窗口内从 1340 rpm 收敛到 0，且 `phi` 基本不动（仿真里额外偏移 <0.05 deg）。

### 4.19 游走的第一版在真机上把参考角拉到钳位（2026-11-06，已回退默认关闭）

**现象**：§4.18 上线后，闭环从"能站十几秒"退化到"两三秒就倒"，并且**慢速来回震荡几次后倒下**，
拔掉 USB 线也一样。15 s / 50 Hz 的 `bal log` 里 `wheel` 一位不变（1043.38 rpm），
而力矩在 ±28 mN·m 之间来回打满；`bal` 屏幕同时显示 `zero = trim -3.00 deg (max 3.00)`、`SATURATED`。

**根因**：游走律把"轮速读数"当唯一信息源。读数一旦滞留在非零值，`trim` 就以 0.3 deg/s 走向钳位；
到 -3 deg 后控制律的等效工作点被搬偏，`kp*3 deg = 69 mN·m` 远超 28 mN·m 上限，长期饱和 → 摆 → 倒。

**处置**（`Code=80288`）：

1. `BAL_TRIM_W_K` 默认改 `0.0f`（宏保留，可 `bal auto on` 现场打开）；
2. `alg_bal_adapt()` 增加两道护栏：**律饱和时冻结**、**每次调用最多移动 0.01 deg（2 deg/s 封顶）**；
3. 顺带修 `%.1e` 打印 bug（原来把 `wheel walk` 打成字面量 `%e`，后面的 `gate` 参数随之错位成 0.00）；
4. L1 用例 18 改为"饱和即冻结、到不了钳位"，并新增 18b（单次 0.01 deg 封顶）。

**教训**：任何"积分某一路测量值"的慢环，都必须先假设该测量会滞留/失真，护栏（饱和冻结、速率封顶、
范围钳位）要和功能一起上线，而不是事后补。

### 4.20 零点改成实测 46.27，并加 `bal snap`（2026-11-06）

`18#T20` 的稳态关系 `omega_ss = 573 rpm/deg x (trim - phi_ss)` 在现场用定点迭代验证：

| 步 | trim | phi | wheel |
|---|---|---|---|
| 0 | 0.44 | 0.89 | -427.5 rpm |
| 1 | 1.19 | 0.89 | +152.1 rpm |
| 2 | 0.92 | 0.78 | +73.4 rpm |
| 3 | 0.79 | 0.90 | -46.2 rpm |

过零点在 `trim ≈ 0.87`，实测灵敏度 610 rpm/deg（模型 573，差 6%，来自摩擦前馈与残余零点）。
加上编译期 `ATT_OFFSET_DEG = 45.4` 得到真实平衡点 **46.27°**（手扶 46.35°、两轮拟合 46.64° 在散布内一致），
因此把 `ATT_OFFSET_DEG` 改成 `46.27f`：上电即零，重启不再带 0.9° 偏置。

同时新增 `bal snap`：一次定点步 `trim -= omega_rpm / (kp/kw in rpm per deg)`，钳位 ±`BAL_TRIM_MAX_DEG`；
仅在 `RUN && engaged` 执行（2），无姿态帧（3），增益非法（4），`abs(omega) > 1200 rpm` 拒绝（5）。
它走 `app_bal_trim_set()`，所以会把轮速游走关掉（手动接管）。

### 4.21 2026-11-10 重新开启游走：护栏 + 运行时 `bal walk`（`docs/00` #076）

#### 为什么当初关掉
2026-11-06 的第一版没有"读数可信"这道门：编码器偶发把轮速冻结在 1043 rpm，游走对着一个常数积分，
10 s 就把 `trim` 推到钳位，机体随后被推倒（`4.19`）。当时的结论是"机制对、输入不可信"。

#### 现在的两道新门
1. **编码器可信**：空闲字节锚定解码 + 单帧接受 + 物理连续性门之后，转动时 `crc` 错误率 0.046%、
   `badrun 0`、`resync` 3 次/小时（`docs/00` #059/#062）。
2. **读数新鲜度护栏**（新增，`app_bal_walk_ready()`）：每帧检查 `mid_enc_info()->frames` 是否变化，
   `valid == 0` 或 100 ms 内没有新帧就冻结游走。20 kHz 下健康链路每 50 µs 前进一帧，
   100 ms 相当于 2000 帧——只有"真的停了"才会触发。

#### 参数与开关
| 项 | 值 | 说明 |
|---|---|---|
| `BAL_TRIM_W_K` | `3e-4` | deg per rpm per s；`sim/s6_auto_trim2.py`：2.3° 零点误差下 70 s 收到 ~0，机体移动 <0.05° |
| `ALG_BAL_TRIM_WK_MAX` | `1e-2` | 运行时上限，防止控制台把增益开到能把 `trim` 瞬间推到钳位 |
| `BAL_WALK_STALE_MS` | `100` | 读数陈旧判据 |
| `bal auto on/off` | 默认 on | 总开关 |
| `bal walk <k>` | 0 冻结 | 现场调增益，不用重烧 |

#### 仿真复跑（2026-11-10，`sim/s6_auto_trim2.py`）
2.3° 零点误差下：`k=1e-4` 36 s 收敛到 17 rpm；`k=3e-4` **17 s 收敛**、尾值 −20 rpm、机体只移动约 0.2°
（`phi` −2.43° → 保持 −2.31°，`trim` −2.26°）；`k=5e-4` 10 s；`k=1e-3` 5 s 但机体偏移 0.7°。
**边界**：零点误差 3.0° 时（`k=1.5e-4`）轮速先顶到 1703 rpm 触发 `trip wheel`，游走来不及救——
所以游走是"慢修正"，松手偏差仍需压在 ~2.5° 以内，不能当"救场"用。

#### 验收标准（上板，待做）
站上去后 `wheel` 单调衰减到 ≤100 rpm，`trim` 停在 ±2° 以内不撞 `BAL_TRIM_MAX_DEG`，
过程中 `saturated` 不应长期为 1。

#### 4.22 首测暴露的两个判据问题（2026-11-11）

| 现象 | 根因 | 修法 |
|---|---|---|
| 松手后 3 s 内必倒，来不及接管 | `BAL_KEY_START_DELAY_MS 3000`：立方体静态不稳定，0.5° 自由发展约 260 ms 即超出 4.5° 捕获窗 | 改为 **300 ms**：松手后 0.3 s 接管，此时手仍扶着、φ≈0，接管瞬间几乎不产生力矩 |
| 慢摆被判成"扶着" | `held` 只看 rate 的绝对值 ≤ 5 °/s，慢摆在转向点角速度天然很小 | 接管后 **800 ms 内不判**（`BAL_HELD_GRACE_MS`），且计数期间角度与计数起点相差超过 `BAL_HELD_PHI_DEG`(0.30°) 即清零 |

新操作姿势：扶稳 → 按键、按完即松手 → 0.3 s 后接管 → **再平稳松手**（不是先松手再按）。
