## 1. 背景

S4 已把平衡律接进固件并跑通影子模式（`docs/00` #024）：真实 IMU 数据经 `mid_att` 得到 θ，
`alg_bal` 算出 `tau_cmd`，`corr(θ, τ) = 0.86`、静态点 `kp` 分力与手算差 0.02%。
但 `app_bal_update()` **全程不调用 `app_torque_set()`**——律在那里算，力矩从来不出去。

S6 要做的是把最后这一根线接上，并且**用一整套联锁把它包起来**：出错时力矩必须自己消失，
而不是等操作者反应。

三件事决定了 S6 不能一次做到"放手平衡"：

| 约束 | 现状 | 对 S6 的含义 |
|---|---|---|
| `18#T19` 物理反作用方向未验证 | 只能靠闭环首测判定 | 首测必须是"判定实验"，不是"展示实验"：允许它倒，不允许它带着满力矩倒 |
| `18#T22` 线缆外力 | 1 N × 5 cm = 50 mN·m > 全部力矩预算 34.7 mN·m | **带线不可能真平衡**；带线阶段只做方向判定，真平衡必须电池 + 无线 |
| `18#T20` 平衡点角度未知 | 现场 `att zero` 得到 46.92°，是手扶位置不是真平衡点 | 无积分时稳态会停在"轮速转起来顶住摩擦"的位置；S6 验收按"角度稳、轮速有界"而不是"轮速为零" |

## 4. 技术路线

### 4.1 编排层：`app_balance`（S6 新增）

放在 `User/App/`，**只做编排**，不做数学（数学在 `alg_bal`），不碰 HAL。

```
app_balance_update()            每轮主循环调用
  ├─ seq 未变 → 直接返回                     （零阶保持，200 Hz 新帧才动）
  ├─ 状态 == DISARMED → 直接返回
  ├─ 取 att_get() → 帧无效 → trip(STALE)
  ├─ 计算 alg_bal_step()  → tau_cmd
  ├─ 限幅：abs(tau) ≤ BAL_MAX_MNM，abs(dtau) ≤ BAL_SLEW_MNM_STEP
  ├─ 检查 TRIP 条件（表 4.3）
  ├─ trip  → app_torque_off(); app_stop(); state = TRIP
  └─ 正常  → app_torque_set(tau); 计时 + 累计统计
```

状态机（**硬优先级**：TRIP > DISARMED > ARMED > RUN，低优先级不得覆盖高优先级状态）：

| 状态 | 进入条件 | 允许的事情 |
|---|---|---|
| DISARMED | 上电、用户 `bal run off`、任何 STOP | 只有影子计算 |
| ARMED | `bal run on` 且 ARM 条件全满足 | 开始输出力矩 |
| RUN | 已输出力矩且未触发 TRIP | 持续输出 |
| TRIP | 任一 TRIP 条件 | 力矩已清零、PWM 已封，等待人工 `bal run off` |

### 4.2 为什么只在"新帧边沿"输出

`app_bal_update()` 现在每轮主循环都跑（~75 kHz），但姿态只有 200 Hz。
如果每轮都调 `app_torque_set()`，同一个 θ 会被施加 375 次，**PID 之外的隐式积分**就出现了：
`kd` 项在帧间保持不变，力矩会一直顶在一个非零值，等效于给系统加了纯摩擦。

正确做法与 L1 仿真一致：**5 ms 零阶保持**。实现上用 `att_get()->seq` 判新帧——
这与 `18#T16` 决定的"200 Hz 固定定时器取最新帧"等价，且不需要新增定时器。

### 4.3 ARM 与 TRIP 条件（全部进 `board_cfg.h`）

| 类别 | 条件 | 初值 | 依据 |
|---|---|---|---|
| ARM | 姿态有效 | `att_get()->valid == 1` | 无姿态不许出力 |
| ARM | `abs(theta) ≤` | `BAL_ARM_DEG 2.5°` | 0.7× 的捕获窗口是 4.50°，留 1.25° 余量（`L-13`：降额后窗口必须重新扫描，0.4× 时窗口是 0.00°） |
| ARM | `abs(theta_dot) ≤` | `BAL_ARM_DPS 30 °/s` | 快速倾倒时不接管 |
| ARM | `abs(omega) ≤` | `BAL_ARM_RPM 300 rpm` | 起手时轮子应基本静止 |
| ARM | 驱动就绪 | `app_torque_set()` 先决条件 | 返回 2/3/4 时拒绝 ARM 并打印原因 |
| TRIP | `abs(theta) >` | `BAL_TRIP_DEG 12°` | 2.73° 已饱和，12° 说明已经倒了 |
| TRIP | `abs(theta_dot) >` | `BAL_TRIP_DPS 200 °/s` | 高速倾倒 |
| TRIP | `abs(omega) >` | `BAL_TRIP_RPM 1700 rpm` | `L-12`：1700 rpm 以上剩余力矩 < 7 mN·m；1200 太紧（零点差 0.5° 就需 ~990 rpm 常值轮速，会在环路还没展开时就跳闸） |
| TRIP | 帧龄 | `> BAL_TRIP_STALE_MS 50 ms` | 200 Hz 下丢 10 帧 |
| TRIP | 故障 | `app_status()->fault != 0` | 过流/过压等直接停 |
| TRIP | 时长 | `> BAL_MAX_MS`（S6a 3000 / S6b 120000） | 首测自动停 |

### 4.4 增益与首测降额

| 阶段 | kp [N·m/rad] | kd [N·m/(rad/s)] | kw [N·m/(rad/s)] | 说明 |
|---|---|---|---|---|
| L1 标称 | 0.728 | 0.0970 | 4.0e-05 | 仿真收敛 ±4.5° |
| S6a 首测 | **0.510** | 0.0679 | 2.8e-05 | **0.7×** 降额（原方案 0.4×，扫出捕获窗口 0.00° 后改）：符号错时发散慢，且仍有 4.50° 窗口 |
| S6b | 0.728 | 0.0970 | 4.0e-05 | 标称，进 S6b 前先用 S6a 确认符号 |

降额通过 `BAL_SCALE` 一个宏实现（0.7 / 1.0），不改 `BAL_KP_*` 原值，避免"调参数把标称值弄丢"。

### 4.5 力矩限幅与速率限制

- 幅值：`abs(tau) ≤ BAL_MAX_MNM (28.0)`，低于 S4 的 34（先于 `app_torque_set` 生效），也低于纹波把相电流峰值顶过 `FOC_I_TRIP_A` 的水平（§4.11）。
- 速率：`abs(dtau) ≤ BAL_SLEW_MNM_STEP (10.0)` 每 5 ms ⇒ **2000 mN·m/s**，0→28 约 14 ms。
  理由：电流环本身很快，真正的风险是**指令跳变**激励机械共振与结构件松动；
  16.5 ms 相对 1.2 Hz 的闭环带宽仍是"足够快"。
- 死区：沿用 `ALG_BAL_TAU_MIN_MNM (1.0)`，避免在零附近抖。

### 4.6 与 `app_torque_set()` 的关系

- 编排层**只**通过 `app_torque_set()` 出力，不直接写 `app_foc_set()`；限幅仍然只有一处。
- `app_torque_set()` 返回 5（超上限）/6（速度环占用）时视为 TRIP，并打印错误码。
- TRIP 的停机顺序固定：`app_torque_off()` → `app_stop()`。
  先清指令再停 PWM，避免"停 PWM 那一拍电流环还拿着旧 iq"。

### 4.7 可观测（这是 S6 能不能调出来的关键）

| 命令 | 内容 |
|---|---|
| `bal run on` / `bal run off` | 显式 ARM / DISARM，打印被拒原因 |
| `bal` | 增加 `arm`/`run` 状态、`trip` 原因码、`tau` 与三项分力、饱和/限幅标志 |
| `bal log <s>` | CSV 增列 `state,trip,tau,phi,rate,rpm`（20 ms 一行，50 Hz） |
| `bal stat` | 本次运行统计：最长连续保持、`abs(theta)` 均方根、饱和占比、最大 `abs(omega)` |

### 4.8 被否掉的备选

| 方案 | 否决理由 |
|---|---|
| 直接在 `app_bal_update()` 末尾调 `app_torque_set()` | 无联锁、无速率限制、无新帧边沿（隐式积分），且出事后无法解释 |
| 用 1 kHz 速度环外挂力矩 | 速度环有积分，会把恒力矩吃掉，且 1 kHz 与 200 Hz 两个环带宽接近会耦合 |
| 用一个独立定时器驱动 200 Hz 闭环 | 与 `18#T16` 结论重复；主循环 + seq 边沿已等价，少一处时基就少一个 bug |
| 首测直接用标称增益 | 符号错时会在 100 ms 内把轮子推到 1200 rpm，来不及断电 |

### 4.9 实现要点（代码与方案的四处偏离，均已验证）

| # | 方案里写的 | 实际采用的 | 为什么 |
|---|---|---|---|
| 1 | "新帧边沿 = `att_get()->seq` 变化" | **IMU 帧计数 `imu_ctx()->stat.frames`** | `mid_att` 每次 `att_update()` 都会自增自己的 `seq`，75 kHz 主循环会让它看起来"每拍都有新帧"，边沿判据形同虚设。L2 用"同一帧重复提交时 `frames` 不增"锁死这条 |
| 2 | "帧龄 > 50 ms 触发 TRIP" | **实时读 `imu_frame_age_ms()`**，不用 `att_state.age_ms` | `age_ms` 只在 `att_update()` 里刷新；IMU 断流时 `att` 不再更新，陈旧值永远小于阈值，联锁会瞎掉 |
| 3 | "编译期断言保证 `BAL_*` 阈值顺序" | **`bal_cfg_load()` 启动告警 + L2 断言** | C 的整数常量表达式不允许浮点操作数，负数组技巧会退化成 VLA（gcc 报 `variably modified at file scope`，ARMCC 同理）。改成启动时 `WARN bal: BAL_* threshold order looks wrong` |
| 4 | 首测降额 0.4× | **0.7×，ARM 窗口 2.5°** | 实测 0.4× 的捕获窗口是 **0.00°**：那套参数 ARM 3° 等于"武装一个已经输了的环路"。0.7× 捕获 4.50°，2.5° 留 1.25° 余量（`sim/s6_scale_scan.py`） |

另外三条实现细节：

- **ARM 会自动打开影子律**（`app_bal_set(1)`），否则编排层拿不到 `tau`。`bal run` 的打印把"律的输出"和"实际下发"分成两个数。
- **TRIP 是锁存的**：TRIP 状态下 `app_balance_arm(1)` 直接拒绝，必须 `bal run off` 清除后再 `mode 2` + `start`。这是 S6a 之前唯一的人工确认环节，不为方便而放开。
- **驱动就绪检查不能借 `app_torque_set(0)`**：零力矩会短路成 `app_torque_off()` 并恒返回 0，测不出任何东西。改为直接看 `app_status()->state == APP_ST_RUN`、`mode == CTRL_FOC`、`s_spd.on == 0`。

### 4.10 轮速单方向累积（`18#T20`）：四条路线只留下摩擦前馈

S6a 第一跑暴露的现象：`phi` 稳定在 0.3°，轮速却一路涨到 754 rpm 并继续爬。这不是失稳，是结构性的。

稳态时力矩方程是 `kp*theta + kw*omega = tau_f + mgh*sin(theta0)`，解出

```
omega_ss = (tau_f - kp*theta0) / kw
```

`kw = 4.0e-5 N.m/(rad/s)` 很小，所以任何常值力矩残差都要用很大的轮速去"兑换"：零点误差 0.2° 就要 1200 rpm，0.5° 直接倒。**电机必须自己付掉库仑摩擦和零点力矩，否则轮子必然单向累积。**

四条路线都试过（`sim/s4_design.py` 的 `simulate()` 已支持全部参数，20 s~120 s、含静摩擦锁死模型）：

| 路线 | 零点误差 0.2° 的结果 | 判定 |
|---|---|---|
| A 轮速积分（4 状态，`ki=1e-5`） | 倒（phi 213°） | ❌ 与静摩擦对抗，反复过冲 |
| B 角度零点自适应（`trim' = k*omega`，clamp ±0.3~1°） | 倒 | ❌ trim 被推到 clamp，`kp*trim` 成了大于 `tau_f` 的常值推力 |
| C 力矩偏置（`bias' = -k*omega`，clamp ±3~4 mN.m） | 倒 | ❌ 方向反了会加剧饱和；方向对了也压不住 `kw*omega` |
| D **摩擦前馈**（`u += sgn(omega)*tau_f`，迟滞带 0.5 rad/s） | **-710 rpm，不倒** | ✅ 采用 |

采用 D 后：零点误差 0° → **-104 rpm**（几乎不转），0.2° → -710 rpm，0.5° → -1620 rpm（会跳闸但不倒）。机理是把常值项直接补上，`kw*omega` 只需兑换剩下的零点误差。脚本 `sim/s6_t20.py`，曲线 `sim/figs/s6_1_t20.png`。

实现要点：
- ff 用**轮子**的符号而不是倾角符号（它补偿的是摩擦，摩擦与轮速反向），带 30 rpm 迟滞防止零速附近抖动；
- ff **不乘** `cfg.sign`：它是物理力矩，不是控制决策，装反了 IMU 不该把它翻过来（L1 16d 锁死这条）；
- 残下的零点误差交给 `bal trim <deg>`：`phi_law = theta - trim`，只改 RAM，重启回 `BAL_TRIM_DEG`，夹在 ±`BAL_TRIM_MAX_DEG`。

### 4.11 力矩上限被相电流纹波吃掉（`BAL_MAX_MNM` 33 → 28 mN·m）

**现象**（2026-11-04 上板，固件 `22;56;21`）：闭环跑到 3.2 s 被 `fault` 打断，`counts oc 1`，
当时 `peaks phi 7.59 deg / wheel 116 rpm / torque 33.00 mN.m / saturated 91`。轮速只有 116 rpm，
说明**前馈把单向累积压住了**（上一版无前馈是 754→1200+ rpm），它不是失效，而是被过流保护误杀。

**根因（解析）**：过流判据比的是**瞬时相电流峰值**，而相电流 = 指令 iq + 开关纹波。纹波
`ΔI_pp = Vbus·D(1−D)/(fsw·L)`，最坏 `D=0.5`，`L=0.5 mH`、`fsw=20 kHz`：

| 母线 | 纹波 p-p | 纹波峰 |
|---|---|---|
| 12.0 V（台架） | 0.300 A | 0.150 A |
| 14.03 V（4S 实测） | 0.351 A | 0.175 A |
| 16.8 V（4S 满电） | 0.420 A | 0.210 A |

于是在 33 mN·m（iq 1.141 A）时峰值电流 = 1.141 + 0.175 = **1.317 A > `FOC_I_TRIP_A` 1.28 A**。
12 V 时就已经是 1.291 A > 1.28 A —— **换电池只是把本来就在边缘的余量彻底顶穿**，
并不是 4S 引入了新问题，而是暴露了旧余量本就不足。

**修法**：`BAL_MAX_MNM 33.0f → 28.0f`（iq 0.969 A）。复算（`sim/s6_ripple.py`）：

| 上限 | iq | 12 V 峰 | 14.03 V 峰 | 16.8 V 峰 |
|---|---|---|---|---|
| 33 mN·m（旧） | 1.141 A | 1.291 TRIP | 1.317 TRIP | 1.351 TRIP |
| 30 mN·m | 1.038 A | 1.188 OK | 1.213 OK | 1.248 OK |
| **28 mN·m（新）** | 0.969 A | 1.119 OK | **1.144 OK** | 1.179 OK |

28 mN·m 在满电 16.8 V 下仍有 0.10 A 余量，且 28 > 捕获窗口需要的力矩（`±2.5°` 时静态需求
`mgh·sin2.5° = 14.3 mN·m`，0.7× 增益的指令更小）。

**为什么不改过流阈值**：`FOC_I_TRIP_A` 1.28 A 已经是采样链路（±1.32 A 饱和）的合理上界，
再往上调就进了 ADC 饱和区，属于**放宽保护**；正确做法是让指令给出足够的纹波余量。

**遗留**：这是"用限幅掩盖判据缺陷"。更彻底的做法是把跳闸判据从瞬时峰值改成滤波后的电流
或 iq/id 矢量幅值（另加一条更快的硬阈值兜底），属保护逻辑重构，放进 S7 鲁棒性阶段。
